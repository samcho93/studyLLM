이번 주의 질문

모델이 준 확률 분포에서 무엇을 고를 것인가? 너무 안전하게 고르면 같은 말을 되풀이하고, 너무 모험하면 말이 안 된다. 그 사이 어디에 설 것인가?

3개념

디코딩 = 분포에서 토큰 하나를 고르는 규칙

언어 모델이 계산한 확률에서 실제 토큰을 고르는 방법을 디코딩 전략(decoding strategy)이라 한다. 이 사이트의 sampling.js는 아래 순서로 한 글자를 고른다. 모델이 내놓은 점수(logit)를 먼저 조정하고, 확률로 바꾼 뒤, 후보를 거르고, 남은 후보에서 뽑는다.

그리디 디코딩: 항상 1등

그리디 디코딩(greedy decoding)은 가장 확률이 높은 토큰만 고른다. 빠르고, 난수가 없어 몇 번을 돌려도 같은 결과가 나온다. 대신 같은 말을 반복하기 쉽다. 위 “왜 필요한가”의 “모든 모든 모든…”이 그 예다. 그리디에게 다음 글자는 문맥의 함수다. “모든 ” 뒤에 “모든”이 1등이면, 한 번 붙인 뒤의 문맥도 “… 모든 모든 ”이 되어 또 “모든”이 1등이 된다. 문맥 창(48글자) 안에 앞 내용이 남아 있어 이 모델은 7번 만에 빠져나왔지만, 빠져나온다는 보장은 없다.

샘플링과 온도: 분포의 모양을 바꾼다

샘플링(sampling)은 확률에 비례해 무작위로 뽑는다. 1주차 C3에서 만든 sampleIndex가 바로 이것이다. 1등이 39%면 열 번 중 네 번쯤만 1등이 뽑히므로 같은 문맥에서도 다른 글이 나온다. 여기에 온도(temperature) T를 넣는다. 점수를 T로 나눈 뒤 소프트맥스를 한다.

P(i) = exp(zᵢ / T) / Σⱼ exp(zⱼ / T)

T < 1이면 점수 차이가 커져 높은 확률의 토큰이 더 강해지고, T > 1이면 차이가 줄어 분포가 평평해진다. T → 0이면 그리디와 같아지고, T → ∞이면 495개가 모두 1/495인 균등 분포가 된다. 아래는 미니 GPT(300스텝)가 “언어 모델” 다음 글자에 낸 실제 분포다.

분포가 얼마나 퍼져 있는지는 엔트로피(entropy) H = −Σ p log₂ p 로 잰다. 단위는 비트(bit)다. 한 글자에 몰려 있으면 0, 495개가 균등하면 log₂ 495 ≈ 8.95 bit다. 2H는 “확률이 고르게 퍼진 후보 몇 개와 맞먹는가”로 읽을 수 있다. 위 T = 1 분포는 23.32 ≈ 10개의 후보가 겨루는 셈이다.

top-k와 top-p: 꼬리를 자른다

샘플링의 위험은 꼬리에 있다. 후보 하나하나는 0.1%로 드물어도 수백 개를 합치면 무시할 수 없다. 이번 주 모델이 “언어 모델은 ” 다음 글자에 낸 분포는 1등이 9.6%에 불과하고, 상위 5개를 모두 합쳐도 25.9%다. 나머지 74%는 수백 개의 꼬리가 나눠 가진다. 그래서 뽑기 전에 꼬리를 자른다.

  • top-k 샘플링: 확률이 높은 k개 토큰 안에서만 뽑는다. 남은 k개의 확률을 합이 1이 되게 다시 나눈다.
  • top-p 샘플링(핵 샘플링, nucleus sampling): 확률을 큰 순서로 더해 p를 넘을 때까지의 토큰 안에서만 뽑는다. 후보 수가 분포 모양에 따라 저절로 바뀐다.
문맥1등 확률엔트로피top-k (k = 5)top-p (p = 0.9)
“언어 모델은 다음” → ?␣ 93.3%0.68 bit5개 (쓸데없는 4개 포함)1개
“언어 모델” → ?은 39.0%3.32 bit5개 (76.7%만 남김)10개
“언어 모델은 ” → ?토 9.6%6.30 bit5개 (25.9%만 남김)93개

top-k는 분포가 뾰족하든 평평하든 늘 k개를 남긴다. 뾰족할 때는 필요 없는 후보를 살려 두고, 평평할 때는 그럴듯한 후보까지 잘라 낸다. top-p는 “확실할 때는 적게, 애매할 때는 많이” 남긴다. 그래서 요즘 LLM API는 주로 온도와 top-p를 함께 쓴다.

반복 페널티: 이미 쓴 글자의 점수를 깎는다

반복 페널티(repetition penalty)는 최근 문맥(이 모델은 48글자)에 이미 나온 토큰의 점수를 깎는다. 점수가 양수면 페널티로 나누고, 음수면 곱한다(CTRL 방식). 1.0이면 끔이다. 그리디의 반복 루프를 끊는 가장 직접적인 방법이다. 다만 이 페널티는 “무엇이 반복인가”를 구분하지 못한다. 한국어에서 공백과 “은 · 을 · 다” 같은 조사 · 어미는 원래 계속 반복되어야 하는 글자인데, 이것들까지 똑같이 깎인다. C4에서 그 대가를 직접 잰다.

유창성과 다양성은 맞바뀐다

분포를 좁히면(낮은 T, 작은 p) 모델이 자신 있는 글자만 쓰므로 글이 매끄럽지만 매번 같은 글, 같은 반복이 나온다. 넓히면 다양해지지만 모델도 드물다고 본 글자가 섞인다. 아래는 C5의 실제 결과다. 유창성은 고른 글자의 “모델 원래 확률”의 로그 평균(0에 가까울수록 모델이 보기에 자연스럽다), 다양성은 distinct-2(서로 다른 2글자 조각의 비율, 1에 가까울수록 반복이 적다)로 쟀다.

빔 서치(beam search)는?

그리디는 한 글자씩 1등만 고르므로 “지금은 2등이지만 이어지는 글까지 합치면 더 그럴듯한” 길을 놓친다. 빔 서치는 매 단계에서 누적 로그 확률이 높은 후보 문장 B개(빔 너비)를 함께 들고 간다. 번역처럼 정답이 거의 하나인 일에는 좋지만, 자유롭게 글을 쓰는 일에서는 그리디보다도 더 밋밋하고 반복적인 글이 나오기 쉽다. 가장 확률이 높은 문장이 사람에게 가장 좋은 문장은 아니기 때문이다. 그래서 채팅용 LLM은 대부분 샘플링(온도 + top-p)을 쓴다. 이번 주는 빔 서치를 구현하지 않는다.

외운 모델에는 손잡이가 듣지 않는다

7주차에서 3000스텝까지 학습시켜 코퍼스를 외운 모델(학습 손실 0.12, 검증 손실 9.40)은 거의 모든 자리에서 분포가 한 글자에 몰려 있다. “언어 모델” 뒤로 80글자를 쓰는 동안 평균 엔트로피가 0.09 bit이고, 80자리 중 78자리가 0.5 bit 미만이다(300스텝 모델은 평균 3.4 bit). 그래서 온도 1로 샘플링해도 원문을 베낀다. seed 1~5로 80글자씩 만들면 평균 98%가 코퍼스에 10글자 이상 그대로 있는 구간이다(300스텝 모델은 0%). 결과가 갈리는 곳은 원문에 갈림길이 있는 자리뿐이다. 온도를 1.5로 올려야 48%, 2.0에서 15%로 떨어진다. 그때는 글도 함께 무너진다. 디코딩은 모델이 준 분포를 다듬을 뿐, 모델이 모르는 것을 만들어 내지 못한다.

🤖

머신러닝 기초와 연결 — 온도는 소프트맥스에 들어가기 전에 점수를 나누는 값일 뿐이다. 머신러닝 기초의 소프트맥스 단원에서 “점수 차이가 클수록 확률이 한쪽으로 몰린다”를 보았다. T로 나누면 그 점수 차이를 키우거나 줄이는 것이다.

4실습

7주차에서 미리 학습해 둔 미니 GPT(300스텝)로 바로 글을 쓴다. 손잡이를 움직이면 그 자리에서 다시 생성한다. 결과는 오른쪽 실행 결과 창에 나온다(휴대폰에서는 위젯 바로 아래). ① 다음 글자 분포는 막대 세 줄로 “모델 원래 → 페널티·온도 적용 → 거른 뒤”를 보여 주고, ② 생성된 글은 글자마다 모델 원래 확률로 색칠한다. 글자를 누르면 그 글자를 고를 때의 분포가 ①에 나온다. seed가 같으면 같은 글이 나온다.

관찰 질문

  1. 처음 화면(샘플링, T = 1, 거르기 없음)에서 ①의 세 막대가 모두 같은 이유는 무엇인가? 빨간 글자(모델 원래 확률 < 10%)를 하나 눌러 본다. 그 순간 1등 후보는 무엇이었고 몇 %였나?
  2. 그리디 → 반복 루프를 누른다. ④ 반복 탐지는 무엇을 찾았나? ③의 5개 샘플은 왜 모두 같은가? seed를 바꿔도 달라지지 않는 이유를 설명한다.
  3. 샘플링으로 돌아와 온도를 0.1 → 1.0 → 2.0으로 움직이며 ①의 엔트로피와 ② 아래의 “평균 log P / 글자”를 기록한다. 어디서부터 글이 무너지는가?
  4. top-p = 0.1 → 사실상 그리디를 누른다. 샘플링인데도 그리디와 거의 같은 글이 나오는 이유를 ①의 “남은 후보 수”로 설명한다. ③에서 5개가 완전히 같지는 않은 이유는?
  5. 그리디로 두고 반복 페널티를 1.0 → 1.2 → 2.0으로 올린다. 루프는 어느 값에서 사라지는가? 2.0에서 띄어쓰기는 어떻게 되는가? ①에서 ↺ 표시가 붙은 글자를 찾아본다.
  6. ▶ 한 글자를 눌러 한 글자씩 만든다. 누르기 전에 ①의 막대를 보고 무엇이 나올지 예상한 뒤 누른다. 예상이 틀린 적이 있다면 그 글자의 “최종” 확률은 얼마였나?
  7. 모델을 3000스텝 (코퍼스를 외운 모델)로 바꾼다. T = 1에서 원문 복사율과 ③의 결과는? 온도를 몇까지 올려야 외운 글이 무너지는가?

C2. top-k와 top-p 거르기★★

고정된 분포(“언어 모델” 다음 후보 8개)에 topK, topP를 구현해 적용한다. 거른 뒤에는 남은 확률의 합이 1이 되게 다시 나눈다. top-p는 “누적 확률이 p에 닿는 토큰까지 포함”한다. 기대 결과: top-p 0.6은 3개(은 61.5% · ␣ 23.1% · 과 15.4%), top-p 0.9는 7개가 남는다. 마지막 줄에서 뾰족한 분포와 평평한 분포에 같은 k, p를 주면 무엇이 달라지는지 확인한다.

function topK(probs, k) {
  if (k <= 0 || k >= probs.length) return probs.slice(); // 0 = 끔
  // TODO: 확률이 큰 순서로 번호를 정렬해 앞 k개만 남기고 나머지는 0, 다시 합이 1이 되게 나눈다
  return probs.slice();
}

  if (p >= 1) return probs.slice();

C5. 디코딩 격자 실험: 유창성과 다양성★★★★

T ∈ {0.5, 1, 1.5} × top-p ∈ {0.5, 0.9, 1.0}의 9칸마다 seed 1, 2로 30글자씩 만든다. 칸마다 ① 평균 log P / 글자(고른 글자의 모델 원래(T = 1) 확률의 로그 평균 — 유창성)와 ② 두 샘플을 합친 distinct-2(다양성)를 표로 만든다. 두 샘플이 같은 글이면 distinct-2가 낮아진다. 표를 보고 “가장 유창한 칸”과 “가장 다양한 칸”이 어디인지, 둘 사이에서 여러분이라면 어느 칸을 고를지 근거와 함께 적는다. 이번에는 generate() 대신 한 글자씩 도는 반복문을 직접 쓴다.

import { deserialize, nextLogits } from '/assets/js/core/gpt.js';
import { softmax, decodeStep } from '/assets/js/core/sampling.js';
import { mulberry32 } from '/assets/js/core/rng.js';
const ckpt = await (await fetch('/assets/data/models/mini-gpt-300.json')).json();
const { model, vocab } = deserialize(ckpt);
const prompt = vocab.encode('언어 모델');
const LEN = 30;
const SEEDS = [1, 2];

/** 한 번 생성하며, 고른 글자마다 모델 원래 확률(T=1)의 로그를 모은다 */
function sample(temperature, p, seed) {
  const rand = mulberry32(seed);
  const ids = [...prompt];
  let logp = 0;
  for (let i = 0; i < LEN; i++) {
    const logits = nextLogits(model, ids);                          // 다음 글자 495개의 점수
    const { index } = decodeStep(logits, { temperature, p, rand }); // 온도 · top-p로 하나 뽑기
    // TODO: 고른 글자의 모델 원래 확률 softmax(logits)[index]의 로그를 logp에 더한다
    ids.push(index);
  }
  return { text: vocab.decode(ids.slice(prompt.length)), logp };
}

6정리 & 다음 주 예고

  • 모델은 다음 토큰의 분포만 준다. 그 분포에서 토큰을 고르는 규칙이 디코딩 전략이고, 같은 모델도 규칙에 따라 전혀 다른 글을 쓴다.
  • 그리디는 결정적이지만 반복 루프에 빠지기 쉽다. 샘플링은 다양하지만 꼬리의 엉뚱한 토큰을 뽑을 수 있다.
  • 온도는 순위를 그대로 둔 채 분포의 뾰족함을 바꾼다. top-k는 개수로, top-p는 누적 확률로 꼬리를 자른다. top-p는 분포 모양에 맞춰 후보 수가 저절로 바뀐다.
  • 반복 페널티는 루프를 끊지만 공백 · 조사처럼 반복되어야 하는 토큰까지 깎는다.
  • 유창성과 다양성은 맞바뀐다. 사실을 답하는 일에는 낮은 온도가, 아이디어를 내는 창작에는 높은 온도가 어울린다. 외운 모델에는 어떤 설정도 새로움을 만들어 주지 못한다.
