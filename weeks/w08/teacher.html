모델은 글을 쓰지 않는다. 495개 글자의 확률표를 낼 뿐이다 → 하나를 고르는 규칙 = 디코딩 전략

1주차 C3의 sampleIndex, 4주차의 소프트맥스, 7주차의 체크포인트가 모두 다시 나온다. 새로 배우는 것은 “분포를 다듬는 손잡이”뿐이라고 안심시킨다.

둘 다 실제 출력이다(프롬프트 “언어 모델”, 80글자, T = 2.0은 seed 1). 위젯의 “그리디 → 반복 루프”, “T = 2.0 → 횡설수설” 버튼으로 그대로 재현된다.

발문: “둘 다 망가졌다. 어떻게 다르게 망가졌나?” → 하나는 너무 안전(반복), 하나는 너무 모험(무작위). 오늘은 그 사이를 찾는다.

그리디 = ① 뒤 1등을 바로 고른다 (②~④, seed 무시)

sampling.js의 decodeStep() 순서 그대로다. ②~④는 순위를 바꾸지 않는다. 순위를 바꿀 수 있는 것은 ① 반복 페널티뿐이다.

라이브러리마다 단계의 순서가 조금씩 다를 수 있다. 개념은 같다고만 짚는다.

그리디는 왜 되풀이하는가

  • 그리디에게 다음 글자는 문맥의 함수다. 난수가 없다
  • “… 모든 ” 뒤 1등이 “모든” → 붙이면 문맥이 또 “… 모든 모든 ” → 또 “모든”
  • 이 모델은 “ 모든”을 7번 되풀이한 뒤 빠져나왔다 (문맥 창 48글자에 앞 내용이 남아 있어서)
  • seed를 바꿔도 5번 모두 같은 글 → 다양성 0

장점도 있다: 빠르고, 재현되고, 모델이 가장 자신 있는 글자만 쓴다

“빠져나온다는 보장은 없다”를 강조한다. 실제 LLM도 낮은 온도에서 같은 문장을 되풀이하는 현상이 있어서 API에 frequency_penalty · presence_penalty 같은 매개변수가 있다.

프롬프트 “검색”으로 그리디를 돌리면 “검색 검색 검색”, “구축 구축 구축”이 나온다. 학생이 다른 프롬프트로 루프를 찾게 해도 좋다.

“언어 모델” 다음 분포의 실제 값이다. T = 2에서 상위 6개 합이 35.9%뿐이고 나머지 64%가 489개 꼬리에 흩어진다 → 횡설수설의 원인.

MLBasic 소프트맥스 복습: 점수를 T로 나누는 것은 점수 차이를 1/T배 하는 것이다. 온도 0은 0으로 나누기라 코드에서는 그리디로 따로 처리한다(decodeStep의 temperature === 0).

top-p = “확실할 때는 적게, 애매할 때는 많이” → API의 기본 조합은 온도 + top-p

top-k는 분포 모양을 모른다. 뾰족할 때(␣ 93%)는 7% 안에 든 엉뚱한 후보 4개를 살려 두고, 평평할 때(1등 9.6%)는 그럴듯한 후보를 대부분 잘라 낸다.

top-p를 핵 샘플링(nucleus sampling)이라고도 부른다는 것을 짚는다. 확률 질량의 “핵”만 남긴다는 뜻이다.

데모 · 샘플링 조절판

시연 순서 (결과는 오른쪽 실행 결과 창)

  1. 처음 화면(샘플링 T = 1): ①의 세 막대가 같다(손잡이를 안 건드렸으니까). 평균 log P −2.60, 빨간 글자가 꽤 많다. ③ 5개 모두 다르다
  2. “그리디 → 반복 루프”: ④에 “ 모든” × 7. ③ 5개 모두 같다. seed 칸 옆에 “그리디는 쓰지 않는다”
  3. 샘플링으로 돌아와 온도 슬라이더를 0.1 → 2.0으로 천천히: 엔트로피 3.32 → 6.47 bit, T = 2.0에서 평균 log P −5.69, “횡설수설” 판정
  4. “top-p = 0.1”: 남은 후보 1개, 그리디와 앞 42글자가 똑같고 80글자 중 68글자가 같은 자리에 같다. 그래도 ③은 5개 중 4개가 다르다(1등이 10% 미만인 자리에서만 갈린다)
  5. ▶ 한 글자: 학생에게 막대를 보고 예상하게 한 뒤 누른다
  6. 모델 → 3000스텝: T = 1인데 원문 복사율 100%, 판정 “원문 베끼기”

생성은 브라우저 메인 스레드에서 한 글자씩 끊어 돌린다. 느린 PC에서는 ③이 1~3초 늦게 채워진다.

실제 API의 frequency_penalty는 나온 횟수에 비례해, presence_penalty는 한 번이라도 나왔으면 깎는다. BPE 토큰이라 공백 문제는 덜하지만 같은 원리다.

왼쪽 위 = 그리디와 같은 글 · 오른쪽 아래 = 횡설수설 · 사실 QA는 왼쪽 위, 창작은 가운데

유창성 = 고른 글자의 모델 원래(T = 1) 확률의 로그 평균. 다양성 = seed 1, 2 두 샘플을 합친 distinct-2(두 글이 같으면 낮아진다).

T = 0.5 · p = 0.5의 seed 1 결과는 그리디 결과와 글자까지 같다(“은 토큰을 보고 다.↵↵↵바이 모델은 모델은…”). T = 1.5 · p = 0.5(−1.97)가 T = 1 · p = 1.0(−2.23)보다 유창하다: top-p가 온도로 부풀린 꼬리를 다시 잘라 주기 때문이다. “온도만 보지 말고 조합을 보라”.

주의: 샘플 2개 × 30글자라 표본이 작다. 결론은 경향으로만 읽는다.

손잡이가 듣지 않는 경우

외운 모델 (3000스텝)

  • 80자리 중 78자리의 엔트로피 < 0.5 bit (평균 0.09)
  • T = 1 샘플링도 원문 복사율 평균 98%
  • T 1.5 → 48%, T 2.0 → 15%

디코딩은 모델이 모르는 것을 만들지 못한다

빔 서치 (참고)

  • 누적 확률이 높은 문장 B개를 함께 들고 간다
  • 번역처럼 정답이 거의 하나인 일에 좋다
  • 자유 생성에서는 더 밋밋하고 반복적이다

채팅 LLM은 대부분 온도 + top-p 샘플링

복사율 = 코퍼스에 10글자 이상 그대로 있는 구간의 비율, seed 1~5 × 80글자 평균. 300스텝 모델은 모든 온도에서 0%다.

외운 모델의 분포도 완전히 한 점은 아니다. “언어 모델은 ” 바로 뒤는 “앞” 60.5% / “바” 38.4%로 갈린다(원문에 “언어 모델은 앞에 …”와 “언어 모델은 바이그램 …”이 둘 다 있다). 그래서 seed마다 다른 문서 조각을 베낀다.

빔 서치는 이번 주에 구현하지 않는다. “가장 확률이 높은 문장이 가장 좋은 문장은 아니다”만 남긴다.

정리

  • 모델은 분포만 준다. 고르는 규칙(디코딩)이 글을 바꾼다
  • 그리디 = 결정적 · 반복 루프 / 샘플링 = 다양 · 꼬리 위험
  • 온도는 모양, top-k는 개수, top-p는 누적 확률 · 페널티는 공백까지 깎는다
  • 유창성 ↔ 다양성: 사실 QA는 낮은 온도, 창작은 높은 온도

function softmaxT(logits, T) {
  const scaled = logits.map((z) => z / T);
  const max = Math.max(...scaled); // 가장 큰 값을 빼도 결과는 같고 exp가 넘치지 않는다
  const exps = scaled.map((z) => Math.exp(z - max));
  const sum = exps.reduce((a, b) => a + b, 0);
  return exps.map((e) => e / sum);
}

function entropyBits(probs) {
  return probs.reduce((h, p) => (p > 0 ? h - p * Math.log2(p) : h), 0);
}

function topK(probs, k) {
  if (k <= 0 || k >= probs.length) return probs.slice();
  const order = probs.map((p, i) => i).sort((a, b) => probs[b] - probs[a]);
  const keep = new Set(order.slice(0, k));
  const out = probs.map((p, i) => (keep.has(i) ? p : 0));
  const s = out.reduce((a, b) => a + b, 0);
  return out.map((p) => p / s);
}

function topP(probs, p) {
  if (p >= 1) return probs.slice();
  const order = probs.map((q, i) => i).sort((a, b) => probs[b] - probs[a]);
  const keep = new Set();
  let cum = 0;
  for (const i of order) {
    keep.add(i);
    cum += probs[i];
    if (cum >= p) break; // p에 닿는 토큰까지 포함한다
  }
  const out = probs.map((q, i) => (keep.has(i) ? q : 0));
  const s = out.reduce((a, b) => a + b, 0);
  return out.map((q) => q / s);
}

/** 같은 조각(1~8글자)이 3번 이상 연달아 나오는 곳: [{ unit, times, at }] */
function findLoops(text, minTimes = 3) {
  const cs = [...text];
  const found = [];
  let i = 0;
  while (i < cs.length) {
    let best = null;
    for (let L = 1; L <= 8; L++) {
      const unit = cs.slice(i, i + L).join('');
      if (!unit.trim()) continue; // 공백만 반복되는 것은 세지 않는다
      let times = 1;
      while (cs.slice(i + times * L, i + (times + 1) * L).join('') === unit) times++;
      if (times >= minTimes && (!best || times * L > best.times * best.unit.length)) best = { unit, times, at: i };
    }
    if (best) {
      found.push(best);
      i += best.times * best.unit.length;
    } else i++;
  }
  return found;
}

/** 두 번 이상 나오는(겹치지 않게) 가장 긴 부분 문자열 */
function longestRepeat(text) {
  let best = '';
  for (let i = 0; i < text.length; i++) {
    for (let L = best.length + 1; i + 2 * L <= text.length; L++) {
      const s = text.slice(i, i + L);
      if (text.indexOf(s, i + L) >= 0) best = s;
      else break;
    }
  }
  return best;
}

function sample(temperature, p, seed) {

  return { text: vocab.decode(ids.slice(prompt.length)), logp };
}
