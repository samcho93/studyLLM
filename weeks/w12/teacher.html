교과목 안내 문서대로 종합 프로젝트 발표는 12주차에 한다. 팀 수가 많으면 Challenge 시간을 줄여 발표에 넘기고 C3도 과제로 돌린다. 휴식 시간에 발표 순서와 노트북 연결을 확인한다.

미니 GPT 체크포인트는 모델당 약 580KB다. 수업 전에 데모 슬라이드를 한 번 열어 두 모델을 모두 캐시에 올려 둔다.

12주의 끝, 오늘 할 일

1~3주언어를 숫자로n-gram · BPE · 임베딩
4~7주GPT를 만든다자동 미분 · 어텐션 · 미니 GPT

12주 지금한계와 RAG모르는 것을 찾아 넣는다
  1. 가중치 속 지식 vs 프롬프트 속 지식 · 환각 · 지식 시점 · 문맥 창
  2. 우리 미니 GPT로 확신도 ≠ 진실을 숫자로 보인다
  3. 검색 → 근거 프롬프트 → 생성: 가장 단순한 RAG를 만들고 잰다

“1주차에 던진 질문 ‘다음 토큰의 확률은?’을 오늘 마지막으로 한 번 더 본다. 이번에는 그 질문에 항상 답해야 한다는 것이 약점이 된다.”

후반부 발표가 있으므로 앞부분은 시간을 지킨다. 타이머(T 키)를 켠다.

“GPU 서버를 한 사람이 연속으로 쓸 수 있는 최대 시간은?”

“GPU 서버는 공정한 배분을 위해 보통 1회 4시간 정도로 제한한다.”

  • 매끄럽고, 자신 있고, 틀렸다 — 정답은 최대 12시간 (실습실 이용 규정)
  • 범용 LLM은 우리 학과 문서를 읽은 적이 없다
  • 그런데 왜 “모른다”고 하지 않을까?

발문: “이 답이 틀렸다는 걸 어떻게 알았나?” → 규정 문서를 봤기 때문. “모델이 규정 문서를 봤다면?” → 오늘의 결론(RAG)을 학생 입으로 먼저 끌어낸다.

같은 질문과 같은 모양의 답으로 RAG 과정 1주차가 시작한다고 예고한다. 위의 인용은 흔한 답의 모양을 보여 주려고 작성한 예시다(실제 호출 결과가 아님).

지식은 두 곳에서 온다

🧠 파라메트릭 (가중치 속)

  • 미니 GPT: 학습 문서 6,470자 → 가중치 106,959개
  • 고치려면 다시 학습
  • 출처를 말할 수 없다
  • 학습이 끝난 시점에서 멈춘다

📄 비파라메트릭 (프롬프트 속)

  • 질문할 때 넣어 주는 글 (11주차 시스템 프롬프트)
  • 문서만 바꾸면 바로 반영
  • 근거 번호로 출처 표시
  • 문맥 창만큼만 넣을 수 있다

비유: 파라메트릭 = 시험 전에 외운 것, 비파라메트릭 = 오픈북 시험에 들고 들어간 책. 외운 것은 틀려도 틀린 줄 모르고, 책은 펼쳐 보여 줄 수 있다.

10주차 파인튜닝도 파라메트릭 쪽이다. “파인튜닝 vs RAG”는 RAG 과정 1주차의 첫 토론 주제다.

분포는 항상 나오고, 1등은 항상 있다

문맥 (mini-gpt-3000)다음 글자 상위 후보엔트로피
“…시간은 최대 ” (외운 문맥)1 100.0% · 연 0.0% · 정 0.0%0.01비트
“벡터 데이터베이스는 ” (학습에서 뺀 주제)하 32.6% · 것 30.8% · 모 9.6% · 방 7.6%2.84비트
  • 소프트맥스 출력의 합은 언제나 1 — “모른다” 전용 출력은 없다
  • “하”를 고른 순간 “이브리드 검색은 두 방식의 결과를 합친다…” (다른 문서)의 궤도에 올라탄다
  • “모른다”는 그런 답을 학습했을 때만 1등이 된다 (10주차 SFT · 선호 학습)

숫자는 mini-gpt-3000의 실제 분포다(학생용 개념 그림과 같다). 첫 글자에서는 망설이지만(엔트로피 2.84비트), 한 글자를 고르면 외운 문장으로 들어가 이후 글자 대부분이 80% 이상이다. 데모에서 글자 위에 마우스를 올려 보여 준다.

발문: “첫 글자에서 엔트로피가 높으면 멈추게 하면 되지 않나?” → 좋은 아이디어이고 실제 연구 주제다. 그러나 ③ 틀린 전제 예제에서는 첫 글자부터 확신한다(“실습실은 별관 5층” 뒤 공백 99.1%).

LLM의 세 가지 한계

한계원인우리 미니 GPT에서
환각1등은 항상 있다“HNSW는” → 다른 문서 조각 이어 붙이기 (확신도 82.8%)
지식 시점가중치는 학습 후 고정뺀 문서(rag-vectordb) = “학습 이후에 생긴 문서”
문맥 창볼 수 있는 토큰 수에 끝이 있다blockSize 48 — 앞 48글자만 본다

실제 LLM의 문맥 창은 수십만 토큰이지만 끝이 있고, 길수록 비싸고 느리다 → 전부 넣지 말고 골라 넣는다

지식 시점을 설명할 때 “학습 문서에서 뺀 문서”가 곧 “학습 이후에 생긴 문서”와 같은 처지임을 강조한다. 7주차 학습기에서 검증 손실을 잰 바로 그 문서다(mini-gpt-3000의 검증 손실 9.40).

문맥 창: 9주차 메모리 계산기와 연결한다. 넣는 글이 길수록 계산과 비용이 커진다.

데모 · 환각 해부

시연 순서 (결과는 오른쪽 실행 결과 창, mini-gpt-3000 · greedy · 50글자)

  1. ① “실습실은 평일 오후” → 확신도 99.4%, 원문 일치 100% (이용 규정). “안다”가 아니라 “외웠다”
  2. ② “벡터 데이터베이스는” → 96.5%, 전부 보라 점선: 하이브리드 검색 문서를 통째로 옮겨 왔다. 두 번째 글자 “하” 위에 마우스 → 33%
  3. ② “HNSW는” → 82.8%, 원문에 없음(빨간 물결)과 다른 문서 조각이 섞인다
  4. ③ “실습실은 별관 5층” → 94.9%, 전제를 고치지 않고 “…6호를 사용하며, 각 실습실에는 GPU가 장착된 PC 30대가 있다”(학과 소개)를 붙인다
  5. “예제 9개 한꺼번에 비교” → ① 99.5% · 3/3, ② 92.1% · 0/3, ③ 92.8% · 0/3
  6. 모델을 mini-gpt-300으로 바꿔 다시 비교 → 49.0% · 51.2% · 48.6%, 정답 0/9. “망설임은 보이지만 쓸모 있는 답도 없다”
  7. ② 탭으로 넘어가 GPU 질문 → 제목 끄고 성적 질문 → 프린터 질문 (다음 두 슬라이드에서 해석)

비교 버튼은 모델당 약 450번의 순전파를 돌리므로 교실 PC에서 몇 초 걸린다. 진행 표시가 나온다.

확신도는 진실을 재지 않는다

mini-gpt-3000 (greedy 50자)평균 확신도정답
① 학습한 사실99.5%3 / 3
② 학습하지 않은 문서92.1%0 / 3
③ 틀린 전제92.8%0 / 3

문장 확률로 따져도: “실습실은 평일 오전 9시부터 오후 6시까지 개방된다”(거짓) −0.639 > “실습실은 평일 오후 9시까지 개방된다”(참) −0.775

확률 = “학습한 글과 얼마나 닮았나” ≠ “사실인가” · 참이 이긴 짝 2 / 5 (Challenge C2)

거짓 문장이 이긴 이유: 앞부분 “평일 오전 9시부터 오후 6시까지”가 학과 소개 문서의 수업 시간 문장과 글자 그대로 같다. 모델은 익숙한 글자열에 높은 확률을 준다.

정직하게 짚을 점: 외운 사실끼리의 짝(12시간 vs 24시간)에서는 참이 크게 이긴다(−0.231 vs −1.603). “확률이 전혀 쓸모없다”가 아니라 “학습 문서와 닮은 정도를 잰다”가 정확한 결론이다.

해결: 근거를 찾아 프롬프트에 넣는다 (RAG)

  1. 검색 (R) — 문단 67개와 질문의 두 글자 조각 겹침 → 상위 2개
  2. 프롬프트 (A) — [1] [2] 번호 붙은 근거 + “근거에 없으면 모른다”
  3. 생성 (G) — “최대 12시간이다[1].” 출처를 확인할 수 있다

모델(가중치)은 그대로. 바뀐 것은 입력에 들어간 문단 두 개

데모 ② 탭: GPU 질문 → 1위 문단 “실습실 이용 규정 #1”(겹침 12개). 근거 없이 ❌ → 근거를 붙이면 ✅. 키가 없으면 “수업용 작성 예시”가 나온다는 점을 먼저 밝힌다.

키가 있으면 “🔑 실제 LLM으로 해 보기”로 실제로 보낸다. 키는 sessionStorage에만 있고 화면 · 로그에 나오지 않는다. 실제 모델은 근거 없이도 “확인이 필요하다”고 답할 수 있다 — 그것도 좋은 토론거리다(10주차 선호 학습의 효과).

RAG는 검색보다 좋아질 수 없다

  • “LLM 원리와 활용 과목의 성적 평가 비율은?” — 성적 문단에는 “LLM”이라는 말이 없다
  • 제목을 붙여 검색: 1위 course-llm-syllabus#2 (겹침 8) → 정답 ✅
  • 제목 없이 검색: 1위 course-llm-syllabus#0, 2위 RAG 과목 문단 → “찾을 수 없다” ❌
  • 답이 문서에 없는 질문(프린터): 올바른 답은 “문서에서 찾을 수 없다”

C5 측정: 검색 적중 5/5인데 답 정답 3/5 → 검색과 생성은 따로 잰다

“문단 앞에 문서 제목 붙이기”는 RAG 과정 4주차(청킹)에서 다루는 “청크에 문맥 붙이기”의 가장 단순한 형태다.

C5의 가짜 LLM이 틀린 두 질문: 성적 질문(“원리 · 활용” 조각이 많이 겹치는 과목 목표 문장을 골랐다), 주말 질문(“실습실” 조각이 겹치는 개방 시간 문장을 골랐다). 검색은 맞았는데 생성이 틀린 경우다. RAG 9주차 평가에서 검색 지표(Recall@k)와 생성 지표(Faithfulness)를 나누는 이유다.

가장 단순한 RAG, 코드 15줄

import { ragPrompt } from '/assets/js/core/llm.js';
const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const paras = corpus.documents.flatMap((d) =>                       // ① 문단으로 나누기
  d.text.split(/\n\s*\n/).map((text) => ({ title: d.title, text: text.trim() })));
const grams = (s) => new Set([...s.toLowerCase().split(/[^0-9a-z가-힣%]+/)]
  .flatMap((w) => [...w].slice(1).map((c, i) => [...w][i] + c)));
const question = 'GPU 서버를 한 사람이 연속으로 쓸 수 있는 최대 시간은?';
const q = grams(question);
const top = paras                                                    // ② 겹치는 두 글자 수로 검색
  .map((p) => ({ ...p, score: [...grams(`${p.title} ${p.text}`)].filter((g) => q.has(g)).length }))
  .sort((a, b) => b.score - a.score).slice(0, 2);
console.table(top.map(({ title, score }) => ({ title, score })));
const { system, messages } = ragPrompt(question, top);               // ③ 근거를 붙인 프롬프트
console.log(system + '\n\n' + messages[0].content);

▶ 실행 결과: 1위 실습실 이용 규정(12), 2위 학과 소개(4), 그리고 llm.js의 ragPrompt가 만든 프롬프트 전문. 질문을 “수료하려면 출석률이 몇 % 이상이어야 하나?”로 바꿔 다시 실행한다(1위 학과 소개 #3, 겹침 4).

이 프롬프트를 LLM에 보내는 한 줄(generate(...))만 더하면 끝이다. 워커 안에서는 키를 읽을 수 없으므로 실제 호출은 위젯 ② 탭에서 한다.

종합 프로젝트 · 성적 30% · 12주차 발표

주제 예시 (3~4명 팀)

필수 조건

  • 과정 부품 2개 이상 사용
  • 평가 세트 5문항 이상 + 숫자 결과
  • 실패 사례 1개 이상과 원인 설명
  • 키 없이도 시연 가능
  • 산출물: 데모 · 1~2쪽 보고서

질의 때 쓸 질문: “정답 포함 여부는 어떻게 판정했나(문자열? 사람?)” · “평가 문항은 누가 만들었나 — 모델이 이미 외운 문장은 아닌가?” · “실패 사례를 고치려면 검색 · 프롬프트 · 모델 중 어디를 바꾸겠나?”

100점 만점을 성적 30%로 환산한다(교과목 안내의 종합 프로젝트 비중).

정리

  • 지식 = 가중치 속(파라메트릭) + 프롬프트 속(비파라메트릭)
  • 1등은 항상 있다 → 환각 · 가중치는 고정 → 지식 시점 · 창에는 끝 → 문맥 창
  • 확신도는 “닮은 정도”이지 “사실”이 아니다
  • RAG = 검색 → 근거 프롬프트 → 생성. 검색과 답은 따로 잰다

function continueText(prompt, n = 50) {
  const ids = vocab.encode(prompt);
  return vocab.decode(generate(model, ids, n, { greedy: true }).ids.slice(ids.length));
}

function longestMatch(text, docs) {
  const chars = [...text];
  let best = { len: 0, text: '', doc: null };
  for (let i = 0; i < chars.length; i++) {
    for (const d of docs) {
      let L = best.len; // only a longer run can win
      while (i + L < chars.length && d.text.includes(chars.slice(i, i + L + 1).join(''))) L++;
      if (L > best.len && d.text.includes(chars.slice(i, i + L).join(''))) {
        best = { len: L, text: chars.slice(i, i + L).join(''), doc: d.id };
      }
    }
  }
  return best;
}

for (const prompt of ['실습실은 평일 오후', '벡터 데이터베이스는', 'HNSW는']) {
  const gen = continueText(prompt);
  const m = longestMatch(gen, train);
  console.log(`“${prompt}” →`, JSON.stringify(gen));
  console.log(`  가장 긴 일치 ${m.len}/${[...gen].length}자 · ${m.doc}:`, JSON.stringify(m.text));
}

function avgLogProb(text) {
  const ids = vocab.encode(text);
  let lp = 0;
  for (let i = 1; i < ids.length; i++) lp += Math.log(softmax(nextLogits(model, ids.slice(0, i)))[ids[i]]);
  return lp / (ids.length - 1);
}

const rows = statements.map((s) => ({ ...s, score: +avgLogProb(s.text).toFixed(3) }));

for (const t of rows.filter((r) => r.truth)) {

function bigrams(s) {
  const out = new Set();
  for (const w of s.toLowerCase().split(/[^0-9a-z가-힣%]+/)) {
    const c = [...w];
    for (let i = 0; i < c.length - 1; i++) out.add(c[i] + c[i + 1]);

  return out;
}

function retrieve(question, k = 2, useTitle = true) {

    .map((p) => {

    })
    .sort((a, b) => b.score - a.score)
    .slice(0, k);
}
