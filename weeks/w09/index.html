잘 외운 모델과 잘 배운 모델

7주차에 학습시킨 미니 GPT는 학습 손실이 0.12까지 내려갔고, 8주차에는 그럴듯한 문장을 뽑아냈다. 그럼 좋은 모델인가? 이번 주는 언어 모델을 숫자로 재는 법(퍼플렉서티)과, 모델을 키울 때 무엇이 얼마나 드는지(메모리와 계산량)를 계산한다. 결론부터 말하면 우리 모델은 처음 보는 문서에서 1주차 바이그램보다도 못하다.

1학습 목표

이번 주가 끝나면
  • 교차 엔트로피 손실을 퍼플렉서티와 bits/글자로 바꾸고, 그 값을 “평균 몇 개 후보 중에서 고민하는가”로 해석할 수 있다.
  • 학습 문서와 검증 문서의 퍼플렉서티를 비교해 과대적합을 찾아내고, 조기 종료 지점을 고를 수 있다.
  • 파라미터 수로 추론·학습 메모리(가중치 · KV 캐시 · Adam)와 학습 계산량(6·N·D)을 어림하고, 70B 모델이 GPU 한 장에 들어가지 않는 이유를 설명할 수 있다.

2왜 필요한가

7주차 미니 GPT를 3,000스텝 학습시키고 “실습실은” 뒤를 이어 쓰게 하면 “실습실은 본관 3층 305호와 306호를 사용하며, 각 실습실에는 GPU가 장착된 PC 30대가 있다.”가 나온다. 완벽한 문장이다. 그런데 이것은 학과 소개 문서의 문장을 한 글자도 틀리지 않고 베낀 것이다. 2,000스텝 때는 “실습실은 30%, 중간 점검 20%, 팀 프로젝트 40% …”처럼 RAG 강의계획서의 성적 비율을 엉뚱하게 이어 붙였다. 생성된 글을 눈으로 보고 모델의 좋고 나쁨을 판단하면 속는다.

두 번째 문제는 크기다. 우리 모델의 파라미터는 106,959개다. 공개된 7B·70B 모델만 해도 그보다 6만~65만 배 크다. 모델을 10배 키우면 메모리는 얼마나 필요하고, 학습에는 GPU 몇 장이 며칠 필요한가? 이 질문에 답하지 못하면 어떤 모델을 쓸지(11·16주차), 어떻게 미세조정할지(10주차) 고를 수 없다.

① 이 모델은 처음 보는 글을 얼마나 잘 예측하는가? (평가) ② 모델을 키우면 메모리와 계산이 얼마나 드는가? (스케일링)

3개념

손실 → 퍼플렉서티 → bits/글자

4주차부터 써 온 교차 엔트로피 손실은 “실제로 나온 다음 글자에 모델이 준 확률”의 음의 로그 평균이다. 1주차 C4의 글자당 NLL과 같은 식이다.

손실 L = −(1/N) Σ ln p(xᵢ | x₁ … xᵢ₋₁)      (단위: nats/글자)
퍼플렉서티 PPL = e^L                        (단위 없음)
bits/글자 = L / ln 2                         (한 글자를 몇 비트로 압축할 수 있나)

손실 4.163은 감이 오지 않지만, e4.163 ≈ 64는 해석할 수 있다. 모든 후보에 똑같은 확률 1/k를 주면 손실은 ln k이고 퍼플렉서티는 정확히 k다. 그래서 퍼플렉서티(perplexity) = “모델이 매 글자마다 평균 몇 개 후보 중에서 고민하는가”로 읽는다. PPL 64인 모델은 매번 64면 주사위를 굴리는 것만큼 헷갈려 한다.

bits/글자(bits per character)는 같은 값을 밑 2로 쓴 것이다. PPL 2 = 1 bit/글자(동전 던지기 한 번), PPL 64 = 6 bits/글자다. 좋은 언어 모델은 곧 좋은 압축기다. 다음 글자를 잘 맞힐수록 적은 비트로 글을 적을 수 있다.

학습 전 미니 GPT(1스텝)의 손실은 6.2018이다. ln 495 = 6.2046이므로 PPL ≈ 494, 즉 495글자 중 아무거나 찍는 것과 같다. 학습이 제대로 시작됐는지 확인하는 첫 번째 점검이 이것이다.

퍼플렉서티를 비교할 때 주의

퍼플렉서티는 토큰 단위에 따라 값이 달라진다. 글자 단위 PPL 64와 BPE 토큰 단위 PPL 64는 다른 뜻이다(토큰 하나가 여러 글자를 담으므로). 어휘와 토크나이저가 같은 모델끼리, 같은 평가 문서로 잰 값만 비교한다. 글자 단위로 통일하고 싶으면 bits/글자를 쓴다.

학습 문서가 아니라 검증 문서로 잰다

모델이 학습한 문서로 재면 “얼마나 잘 외웠나”를 잴 뿐이다. 그래서 문서 하나(“벡터 데이터베이스와 인덱스”, rag-vectordb, 356자)를 학습에서 빼 두었다. 이것이 검증 세트(validation set)다. 1주차 C5에서 n-gram을 평가할 때와 같은 문서다. 네 모델을 같은 방법으로 재면 다음과 같다.

학습을 오래 할수록 학습 문서의 PPL은 1에 다가가고, 검증 문서의 PPL은 폭등한다. 3000스텝 모델은 학습 문서에서 매 글자를 거의 확신하지만(평균 1.14개 후보) 처음 보는 문서에서는 평균 1만 5천 개 후보 중에서 헤맨다. 어휘가 495자뿐이니 “아무렇게나 찍기(495)”보다도 나쁘다. 틀린 글자에 강한 확신을 주기 때문이다. 이것이 과대적합(overfitting)이다.

학습 중에 50스텝마다 두 손실을 기록해 두면 과대적합이 시작되는 지점이 보인다.

검증 손실이 가장 낮은 지점의 가중치를 저장해 두고 쓰는 것을 조기 종료(early stopping)라 한다. 우리 모델이라면 150스텝이다. 그래프의 손실은 학습 도중 무작위 48글자 창 24개로 빠르게 잰 값이라 위 표(문서 전체를 48글자 창으로 잘라 잰 값)와 조금 다르다.

낮은 퍼플렉서티 ≠ 참

퍼플렉서티는 “그럴듯한 글자 배열인가”를 잰다. “실습실은 … 평일 오후 9시까지 개방된다”(참)와 “3시까지”(거짓)의 바이그램 PPL은 32.8과 30.8이다. 거짓 문장이 더 낮다. GPT-300도 5.73과 6.01로 거의 같다. 사실 여부를 가리려면 다른 평가(정답 비교, 근거 확인)가 필요하다. 12주차 환각과 RAG의 출발점이다.

🤖

머신러닝 기초와 연결 — 학습/검증 분할, 학습 곡선, 과대적합, 조기 종료는 머신러닝 기초의 “모델 평가와 과대적합” 단원에서 본 것과 똑같다. 달라진 것은 정확도 대신 퍼플렉서티로 잰다는 것뿐이다.

스케일링: 파라미터 N, 토큰 D, 계산량 C

우리 모델이 외운 이유는 간단하다. 파라미터 106,959개에 비해 서로 다른 학습 글자가 6,470자뿐이다. 3,000스텝 × 배치 16 × 48글자 = 2,304,000글자를 봤으니 같은 글을 약 356번(epoch) 반복했다. 큰 LLM이 외우지 않고 일반화하는 가장 큰 이유는 데이터가 모델보다 훨씬 많기 때문이다.

모델 크기와 데이터 양, 학습 계산량 사이에는 자주 쓰는 어림식이 있다.

  • 학습 계산량 C ≈ 6 · N · D FLOPs. N = 파라미터 수, D = 학습 토큰 수. 토큰 하나마다 순전파에 약 2N, 역전파에 약 4N번의 곱셈·덧셈이 든다(어텐션 계산은 무시한 근사).
  • Chinchilla 어림: D ≈ 20 · N. 계산량이 정해져 있을 때 손실을 가장 낮추려면 파라미터 1개당 서로 다른 토큰 약 20개로 학습하라는 경험칙이다(2022년 Chinchilla 연구). 요즘 모델은 추론 비용을 줄이려고 이보다 훨씬 많은 토큰으로 작은 모델을 학습시키기도 한다.

A100급 GPU를 약 312 TFLOPS(16비트 행렬 연산)로 보고 실제 활용률을 40%로 가정한 추정이다. 70B를 몇 달 안에 학습하려면 GPU 수천 장이 필요하다. 참고로 우리 미니 GPT 3,000스텝(6ND ≈ 1.48 × 10¹² FLOPs)은 JavaScript 엔진으로 Node에서 약 25분 걸렸다(중간 평가 포함). 초당 약 10억(1 GFLOPS) 번 계산한 셈이다.

메모리: 가중치 · KV 캐시 · 학습 상태

① 가중치 = 파라미터 수 × 파라미터당 바이트. 정밀도를 낮추면(양자화, quantization) 줄어든다.

모델fp32 (4B)fp16·bf16 (2B)int8 (1B)int4 (0.5B)
우리 미니 GPT428KB214KB107KB53.5KB
1B4GB2GB1GB0.5GB
7B28GB14GB7GB3.5GB
70B280GB140GB70GB35GB

70B 모델은 fp16으로 가중치만 140GB다. 현재 가장 큰 데이터센터 GPU 한 장(80GB)에 들어가지 않는다. 적어도 두 장에 나눠 싣거나 int8·int4로 줄여야 한다.

② KV 캐시. 8주차에 한 글자씩 생성할 때 앞 토큰들의 키(K)와 값(V)을 매번 다시 계산하지 않고 저장해 둔다. 토큰마다, 층마다 K와 V가 쌓인다.

KV 캐시 = 2(K, V) × 층 수 × KV 헤드 수 × 헤드 차원 × 문맥 길이 × 바이트 × 배치

7B 대표 설정(32층, 헤드 32개 × 128차원, fp16)이면 토큰 하나에 2 × 32 × 32 × 128 × 2 = 524KB다. 문맥 4,096토큰이면 2.15GB, 128K토큰이면 68.7GB로 가중치(14GB)보다 커진다. 동시 사용자(배치)만큼 또 곱해진다. 그래서 요즘 모델은 KV 헤드 수를 줄인다(GQA: 여러 쿼리 헤드가 K·V를 나눠 씀). 70B 대표 설정은 KV 헤드가 8개라 토큰당 328KB로 7B보다 오히려 작다.

③ 학습 상태. 학습하려면 가중치 말고도 기울기와 Adam 옵티마이저 상태가 파라미터마다 따라다닌다. 혼합 정밀도(mixed precision) 학습에서 흔한 구성은 다음과 같다.

① 퍼플렉서티 측정기

모델과 글을 고르면 글자마다 모델이 얼마나 놀랐는지(−ln p)를 색으로 칠하고, 손실 · 퍼플렉서티 · bits/글자를 계산한다. 아래 표는 같은 글을 다른 모델로 잰 값이고, 그래프는 학습 곡선이다. 체크포인트 세 개(각 약 0.6MB)를 불러오므로 처음에 몇 초 걸린다. 결과는 오른쪽 실행 결과 창에 나온다(휴대폰에서는 위젯 바로 아래).

관찰 질문

  1. 처음 화면(오래 학습한 모델 · 검증 문서)의 PPL과 학습 문서 평균 PPL을 적는다. 몇 배 차이인가? 빨간 글자가 몰린 곳은 어디인가(영어 약어, 숫자, 처음 보는 단어)?
  2. “외운 문서” 버튼을 누른다. 초록색이 대부분인 이유는? 이 PPL로 모델을 평가하면 왜 안 되는가?
  3. 검증 문서를 둔 채 모델을 바이그램 → 300 → 800 → 3000으로 바꾼다. 검증 PPL이 가장 낮은 모델은? 학습 곡선의 초록 동그라미(검증 최저)과 연결해 설명한다.
  4. “참 vs 거짓 문장”을 누르고 네 모델의 표를 본다. 거짓 문장의 PPL이 참 문장보다 낮은 모델이 있는가? 오래 학습한 모델에서 차이가 커지는 것은 “이해”인가 “암기”인가?
  5. “섞은 문장”과 “직접 입력”으로 자신만의 문장을 넣어 본다. 학과 문서에 나올 법한 문장과 전혀 다른 주제의 문장은 PPL이 어떻게 다른가?

② LLM 메모리 계산기

파라미터 수, 정밀도, 문맥 길이, 배치를 바꾸면 가중치 · KV 캐시 · 학습 메모리를 로그 눈금 막대로 그리고 GPU 8 / 24 / 80GB와 비교한다. 아래에서 학습 토큰 수를 고르면 6ND 계산량과 GPU 시간을 어림한다. 모든 값은 추정치다(활성값·프레임워크 오버헤드 제외).

관찰 질문

  1. 처음 화면(7B · fp16 · 문맥 4K)은 어떤 GPU에 들어가는가? int8, int4로 바꾸면 어떻게 되는가?
  2. “70B fp16” 버튼을 누른다. 추론에 80GB GPU가 몇 장 필요한가? 학습(Adam)에는?
  3. “7B · 문맥 128K”를 누른다. KV 캐시가 가중치보다 커지는 문맥 길이는 대략 얼마부터인가? 배치를 8로 올리면?
  4. 프리셋을 “우리 미니 GPT”로 바꾼다. 토큰/파라미터는 Chinchilla 어림과 비슷한데 왜 과대적합했는가? 경고 문구를 읽고 설명한다.
  5. 7B를 D = 20N으로 학습할 때 A100급 1,000장이면 며칠 걸리는가? 활용률 40% 가정이 바뀌면 결과는 어떻게 달라지는가?

C2. 검증 문서의 퍼플렉서티 재기★★

학습에서 뺀 rag-vectordb 문서로 바이그램과 미니 GPT(300스텝)의 퍼플렉서티를 잰다. GPT는 문서를 48글자(blockSize) 창으로 잘라 forward에 넣고, 행마다 실제 다음 글자의 −ln softmax를 더한다. 기대 결과: 바이그램 4.163(PPL 64.3), GPT-300 4.274(PPL 71.8). 처음 보는 문서에서는 신경망이 빈도표를 이기지 못한다.

6정리 & 다음 주 예고

  • 퍼플렉서티 = e손실 = “평균 몇 개 후보 중에서 고민하는가”. bits/글자 = 손실 / ln 2. 같은 토크나이저, 같은 평가 문서끼리만 비교한다.
  • 학습 문서의 PPL은 암기를 잰다. 반드시 학습에서 뺀 검증 문서로 잰다. 검증 손실이 가장 낮은 지점에서 멈추는 것이 조기 종료다(우리 모델은 150스텝).
  • 낮은 PPL은 “그럴듯함”이지 “사실”이 아니다. 거짓 문장도 PPL이 낮을 수 있다.
  • 학습 계산량 ≈ 6·N·D, Chinchilla 어림 D ≈ 20N(서로 다른 토큰). 우리 모델은 비율은 맞았지만 같은 6,470자를 356번 반복해서 외웠다.
  • 메모리 = 가중치(N × 바이트) + KV 캐시(문맥 × 배치에 비례). 학습은 파라미터당 약 16바이트. 70B는 fp16 가중치만 140GB라 80GB GPU 한 장에 들어가지 않는다.

RAG 과정과 연결 — RAG 9주차 “평가 데이터셋 & 측정”에서는 검색기를 Recall@k로 잰다(“정답 문서가 상위 k개 안에 들었나”). 퍼플렉서티가 “다음 글자를 얼마나 잘 맞히나”를 재듯, Recall@k는 “필요한 문서를 얼마나 잘 찾나”를 잰다. 둘 다 정답을 아는 평가 세트를 따로 떼어 두는 것에서 시작한다. 그리고 오늘 본 것처럼 PPL이 낮아도 사실을 보장하지 않기 때문에, RAG는 답의 근거가 되는 문서를 찾아 넣는다.
