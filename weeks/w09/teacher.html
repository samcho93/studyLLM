퍼플렉서티 = 평균 몇 개 후보 중에서 고민하는가

손실 L = −(1/N) Σ ln p(실제 다음 글자)     nats/글자
PPL   = e^L                                평균 후보 수
bpc   = L / ln 2                           bits/글자
상황손실PPLbits
동전 (후보 2개 균등)0.69321
바이그램 · 처음 보는 문서4.16364.36.01
495자 균등 = 학습 전 GPT6.205 (6.202)495 (494)8.95

학습 전 미니 GPT의 1스텝 손실 6.2018은 ln 495 = 6.2046과 거의 같다. “학습 시작 손실이 ln(어휘 크기) 근처인가”는 학습 코드가 제대로 짜였는지 보는 첫 점검이다.

PPL은 기하평균의 역수다: 확률들의 기하평균이 1/64이면 PPL 64. 다음 슬라이드 코드에서 “확률 0이 하나라도 있으면 PPL = ∞”를 보여 준다.

주의: 토큰 단위가 다르면 PPL을 비교할 수 없다. 글자 PPL과 BPE 토큰 PPL은 다른 척도다.

PPL을 손으로 계산해 보기

// 퍼플렉서티 = e^(평균 −ln p) = "평균 몇 개 후보 중에서 고민하는가"
for (const k of [2, 10, 64, 495]) {
  const loss = -Math.log(1 / k); // k개 후보에 똑같은 확률
  console.log(`후보 ${k}개 균등: 손실 ${loss.toFixed(3)} → PPL ${Math.exp(loss).toFixed(1)} · ${(loss / Math.LN2).toFixed(2)} bits`);
}
// 세 글자는 확신(p = 0.9), 한 글자는 헤맴(p = 0.01)
const ps = [0.9, 0.9, 0.9, 0.01];
const loss = -ps.reduce((s, p) => s + Math.log(p), 0) / ps.length;
console.log('섞인 경우: 손실', loss.toFixed(3), 'PPL', Math.exp(loss).toFixed(2));
console.log('확률 0이 하나라도 있으면 PPL =', Math.exp(-Math.log(0))); // 한 번의 “절대 불가능”이 전체를 망친다

실행 결과: 후보 2개 → PPL 2.0 · 1.00 bits / 10개 → 10.0 · 3.32 / 64개 → 64.0 · 6.00 / 495개 → 495.0 · 8.95. 섞인 경우 손실 1.230, PPL 3.42. 확률 0 → Infinity.

세 글자는 거의 확신(0.9)했는데 한 글자에서 크게 헤매면(0.01) PPL이 3.42로 뛴다. 평균이 산술평균이 아니라 로그 평균이라 “크게 놀란 글자”에 민감하다. 1주차에 스무딩이 필요했던 이유와 같다.

문장 ①은 “실습실은 수업 시간 외에도 평일 오후 9시까지 개방된다.”(실습실 이용 규정 원문). ②는 숫자 하나만 바꿨다. ③은 ①을 seed 9로 섞은 “9시에방실실평습 다 지오간개된일수외 도은시. 후까 업”.

우리 모델: 2,304,000글자를 봄 = 토큰/파라미터 21.5 — 그러나 같은 6,470자를 356번

6ND: 토큰 하나당 순전파 약 2N, 역전파 약 4N번의 곱셈·덧셈(어텐션 연산 무시). A100급을 약 312 TFLOPS × 활용률 40%로 가정한 추정이다. 정확한 숫자보다 “자릿수”를 읽게 한다.

Chinchilla 어림은 서로 다른 토큰 기준이다. 6,470자에 맞는 모델은 약 324개 파라미터 — 우리 모델은 약 331배 크다(C5). 실측: 우리 JS 엔진은 1,000스텝(6ND ≈ 4.9×10¹¹)에 499초 → 약 1 GFLOPS.

최근 모델은 추론 비용을 줄이려 20N보다 훨씬 많은 토큰으로 작은 모델을 학습하기도 한다는 점을 덧붙인다(어림식은 출발점일 뿐).

70B는 왜 GPU 한 장에 안 들어가나

추론

  • 가중치 = N × 바이트 → 70B fp16 = 140GB > 80GB
  • int8 70GB · int4 35GB (양자화)
  • KV 캐시 = 2 × 층 × KV헤드 × 헤드차원 × 문맥 × 바이트 × 배치
  • 7B · 128K 문맥 → KV 68.7GB > 가중치 14GB

학습 (Adam, 혼합 정밀도)

  • 가중치 2 + 기울기 2 + fp32 원본 4 + m 4 + v 4 = 16B/파라미터
  • 7B → 112GB · 70B → 1.12TB
  • + 활성값 (배치 × 길이에 비례)

모든 값은 “대표 설정 예시”(7B: 32층 · 헤드 32 × 128, 70B: 80층 · KV 헤드 8 × 128) 기준 추정이다. 1GB = 10⁹바이트.

KV 캐시는 8주차 생성 루프와 연결한다: 새 토큰마다 앞 토큰의 K·V를 다시 계산하지 않도록 저장한다. 70B가 토큰당 KV 328KB로 7B(524KB)보다 작은 이유는 GQA(KV 헤드 8개).

발문: “16바이트 중 학습이 끝나면 버려도 되는 것은?” → 기울기, fp32 원본, Adam 상태. 추론은 2바이트면 된다.

        const row = logits.data.subarray(t * V, (t + 1) * V);
        let mx = -Infinity;
        for (const v of row) mx = Math.max(mx, v);
        let se = 0;
        for (const v of row) se += Math.exp(v - mx);
        sum += Math.log(se) + mx - row[ids[start + t + 1]];
        count++;
      }
    }
  });
  return sum / count;
}

for (const step of [300, 800, 3000]) {
  const res = await fetch(`/assets/data/models/mini-gpt-${step}.json`);
  if (!res.ok) continue; // 없는 체크포인트는 건너뛴다
  const { model, vocab } = deserialize(await res.json());
  const loss = valLoss(model, vocab.encode(valText));
  rows.push({ 모델: `GPT-${step}`, loss: +loss.toFixed(3), ppl: +Math.exp(loss).toFixed(1) });
}

정답 코드는 체크포인트 세 개를 모두 잰다(스켈레톤은 300만). 창 경계에서 문맥이 끊기므로(각 창의 첫 글자는 문맥 1글자) 학습 중 기록(meta.history, 무작위 창)의 값과 조금 다르다. 창을 겹쳐 밀면(stride < 48) 더 정확해진다 — 심화 과제로 낼 수 있다.

자주 틀리는 곳: Math.exp를 그대로 더해 Infinity가 나오는 경우 → 최댓값을 빼는 log-sum-exp 요령. 타깃을 ids[start + t]로 잡아 “현재 글자”를 맞히는 경우(손실이 비정상적으로 낮다).

function earlyStop(hist, patience) {
  let bestVal = Infinity;
  let bad = 0;
  for (const h of hist) {
    if (h.val < bestVal) {
      bestVal = h.val;
      bad = 0;
    } else if (++bad >= patience) return h.step;
  }
  return null;
}
