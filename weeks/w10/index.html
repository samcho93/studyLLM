1학습 목표

이번 주가 끝나면
  • 사전학습, 지시 미세조정(SFT), 선호 학습(RLHF·DPO)이 각각 어떤 데이터로 무엇을 학습하는지 설명할 수 있다.
  • 대화를 채팅 템플릿 문자열로 바꾸고, 어시스턴트의 토큰만 학습하는 손실 마스크를 만들 수 있다.
  • LoRA의 학습 파라미터 수와 메모리를 계산해 전체 미세조정과 비교할 수 있다.

2왜 필요한가

7주차의 미니 GPT에 “실습실은 몇 시까지 이용할 수 있어?”를 넣으면 답이 나오지 않는다. 모델은 이 글이 어떤 문서의 앞부분이라고 보고 다음 글자를 이어 쓸 뿐이다. 수천억 개 토큰으로 학습한 거대한 모델도 사전학습만 했다면 마찬가지다. 질문 한 줄 뒤에 또 다른 질문을 늘어놓거나, 소설의 대사처럼 이어 쓴다.

그런데 ChatGPT의 몸체도 같은 디코더 트랜스포머다. 어텐션도, 다음 토큰 예측도 그대로다. 차이는 사전학습 뒤에 한 추가 학습에 있다. 여기서 두 가지 질문이 나온다.

  1. 무엇을 어떻게 더 학습시키면 “이어 쓰기”가 “대답하기”로 바뀌는가?
  2. 80억 개 파라미터 모델을 다시 학습시키려면 메모리가 128GB를 넘는다. 학생 GPU 한 장(24GB)으로는 어떻게 하는가?
이번 주의 한 줄

모델 구조는 그대로다. 바뀌는 것은 데이터(대화 형식), 손실(답에서만 계산), 그리고 학습하는 파라미터(LoRA는 1%도 안 된다)다.

핵심은 ②다. SFT의 손실 함수는 4주차에 만든 교차 엔트로피와 완전히 같다. 다른 점은 딱 두 가지다. 학습 문서가 “대화 형식의 문자열”이라는 것, 그리고 그 문자열의 일부에서만 손실을 계산한다는 것이다.

채팅 템플릿: 대화를 문자열 하나로

모델이 받는 입력은 언제나 토큰 열 하나다. 그래서 “시스템 지시문, 사용자 질문, 어시스턴트 답”이라는 대화 구조를 문자열 하나에 담는 약속이 필요하다. 이것이 채팅 템플릿(chat template)이다. 차례마다 시작과 끝을 특수 토큰으로 표시하고, 역할 이름을 적는다. 아래는 ChatML 형식이다.

<|im_start|>system
너는 AI응용소프트웨어과 학생을 돕는 조교다. 학과 규정에 근거해 짧게 답한다.<|im_end|>
<|im_start|>user
실습실은 몇 시까지 이용할 수 있어?<|im_end|>
<|im_start|>assistant
평일에는 오후 9시까지 이용할 수 있다. 주말과 공휴일에는 사전 신청한 학생만 쓸 수 있다.<|im_end|>

<|im_start|>는 글자 12개처럼 보이지만 어휘에 따로 추가된 토큰 하나다. 사용자가 이 글자를 그대로 쳐도 같은 토큰이 되지 않도록 토크나이저가 따로 다룬다. 템플릿은 모델마다 다르다(아래 표는 간략화한 형태다. 실제 템플릿에는 도구 호출, 기본 시스템 문구 같은 부분이 더 붙는다).

ChatML (Qwen 등)<|im_start|>user↵<|im_end|>system 차례가 있다

추론할 때는 마지막 사용자 차례 뒤에 어시스턴트 머리말만 붙여 넣는다(ChatML이면 <|im_start|>assistant↵). 이것을 생성 프롬프트(generation prompt)라 한다. 모델은 “이제 내 차례”임을 알고 답을 쓰다가, SFT에서 배운 대로 <|im_end|>를 내면 멈춘다. 실제 챗봇의 디코딩 루프는 이 토큰이 나오면 멈춘다(8주차의 미니 GPT는 정해진 길이만큼 뽑았다).

손실 마스크: 답만 학습한다

위 대화를 글자 단위 토큰(특수 토큰은 1개)으로 세면 146토큰이다. 이 중 손실을 계산하는 것은 어시스턴트의 답 51토큰과 그 끝의 <|im_end|> 1토큰, 합해서 52토큰(35.6%)뿐이다. 나머지 자리의 정답은 −100으로 바꿔 손실 계산에서 뺀다(PyTorch 교차 엔트로피의 ignore_index).

왜 사용자 차례를 학습하지 않을까? 질문은 추론 때 사용자가 주는 것이라 모델이 만들 필요가 없고, 학습하면 오히려 “사용자처럼 질문을 지어내는” 습관이 든다. 반대로 템플릿 없이 대화를 그냥 이어 붙여 전부 학습하면(사전학습과 같은 방식) 누가 말하는지 표시가 없어 언제 멈춰야 할지도 모른다. 실습 위젯에서 두 경우를 모두 볼 수 있다.

선호 학습: RLHF와 DPO

SFT만 해도 질문에 답은 한다. 그러나 “맞지만 불친절한 답”, “장황한 답”, “위험한 요청에 순순히 따르는 답”도 모범 답을 흉내 낸 결과일 수 있다. 좋은 답을 사람이 매번 새로 쓰는 것은 비싸지만, 답 두 개 중 어느 쪽이 나은지 고르는 것은 훨씬 쉽다. 선호 학습은 이 선택을 데이터로 쓴다.

  • RLHF(Reinforcement Learning from Human Feedback): ① 선호 쌍으로 “답에 점수를 매기는” 보상 모델을 따로 학습한다. ② 챗봇이 답을 생성하고, 보상 모델의 점수가 높아지도록 강화학습(PPO 등)으로 고친다. 이때 SFT 모델에서 너무 멀어지지 않게 벌점을 준다. 학습 중에 여러 모델(챗봇, 기준 모델, 보상 모델 등)을 함께 돌려야 해서 복잡하고 불안정하다.
  • DPO(Direct Preference Optimization): 보상 모델 없이 선호 쌍으로 바로 학습한다. 고른 답 yw와 버린 답 yl에 대해, 학습 중인 모델 πθ가 기준 모델(SFT 모델) πref보다 yw의 로그 확률은 더 올리고 yl은 더 내리도록 한다.
margin = β × [ (log πθ(y_w) − log π_ref(y_w)) − (log πθ(y_l) − log π_ref(y_l)) ]
loss   = −log σ(margin)            σ: 시그모이드, β: 기준 모델에서 벗어나는 정도를 조절 (예: 0.1)

DPO의 손실은 이진 분류의 로지스틱 손실과 모양이 같다. “고른 답 쪽이 이긴다”를 정답으로 하는 분류 문제로 바꾼 셈이다.

전체 미세조정은 왜 비싼가

SFT든 DPO든, 모든 파라미터를 학습하면(전체 미세조정, full fine-tuning) 파라미터 하나마다 가중치만이 아니라 기울기와 옵티마이저 상태까지 메모리에 올라간다. 혼합 정밀도로 AdamW를 쓸 때 흔히 쓰는 어림셈은 파라미터당 16바이트다.

fp16/bf16 기울기2
fp32 가중치 원본 (갱신용)4

Llama 3 8B급 모델(8,030,261,248개)이면 16바이트 × 80억 = 128.5GB다. 학습 중 활성값(activation)은 빼고도 그렇다. 24GB GPU라면 6장 분량이다. 9주차의 메모리 계산기에서 본 “추론에 필요한 메모리”와 비교하면 학습이 얼마나 무거운지 알 수 있다.

LoRA: 작은 행렬 두 개만 학습한다

LoRA(Low-Rank Adaptation)는 원래 가중치 W를 동결하고, 그 옆에 작은 행렬 두 개 A와 B를 붙여 그것만 학습한다. 미세조정으로 바뀌는 양 ΔW가 “낮은 rank의 행렬로 충분히 표현된다”는 가정이다.

  • 파라미터 수: 층 하나가 din × dout이면 LoRA는 r × (din + dout)개다. 8B급 모델의 모든 선형층(q·k·v·o·MLP)에 r = 16을 붙이면 41,943,040개, 전체의 0.52%다.
  • 초기화: A는 작은 무작위 값, B는 0이다. 그래서 B·A = 0이고, 학습 첫 순간의 모델은 원래 모델과 똑같다. 망가진 상태에서 출발하지 않는다.
  • α/r: 변화량의 배율이다. α를 고정해 두면 r을 바꿔도 학습률을 다시 맞출 필요가 적다.
  • 메모리: 기울기와 Adam 상태는 A·B에만 생기지만, 동결된 W는 그대로 메모리에 있어야 한다. 8B급을 bf16으로 올리면 16.1GB, 학습 부분까지 약 16.7GB다. QLoRA는 이 동결 가중치를 4비트로 양자화해 약 6.3GB로 줄인다(모두 활성값을 뺀 추정치).
  • 한계: rank r이면 ΔW도 rank가 r 이하다. 너무 작으면 바꿀 수 있는 “방향”이 모자란다. 반대로 작은 모델에서 r을 키우면 LoRA가 원래 층보다 커진다. 미니 GPT의 48×48 층은 r = 24에서 같아진다.

RAG 과정과 연결 — 미세조정은 말투, 형식, 과제 수행 방식을 바꾸는 데 강하다. 그러나 새 사실을 넣는 데는 약하다. 문서가 바뀔 때마다 다시 학습해야 하고, 답의 근거를 보여 줄 수도 없다. 그래서 “새 지식을 넣으려면 미세조정보다 RAG가 먼저다.” RAG 1주차의 “그냥 묻기 · 파인튜닝 · 문서 붙이기 · RAG” 비교표를 다시 본다.

4실습

위젯 두 개로 이번 주 개념을 직접 확인한다. 결과는 오른쪽 실행 결과 창에 나온다(휴대폰에서는 위젯 바로 아래).

4-1. 채팅 템플릿 뷰어

메시지를 고치거나 더하면 모델이 실제로 보는 문자열이 바로 바뀐다. 보라색 칩이 특수 토큰이고, 초록 밑줄이 손실을 계산하는 자리다. 토큰은 미니 GPT처럼 글자 하나를 1개로, 특수 토큰도 1개로 센다. 아래 “실패 사례” 단추는 수업용으로 작성한 예시를 보여 준다(실제 모델을 돌린 결과가 아니다).

관찰 질문

  1. 기본 대화(ChatML)에서 전체 토큰 수, 학습 토큰 수, 학습 비율을 기록한다. 학습 토큰에는 무엇과 무엇이 들어 있는가?
  2. 템플릿을 Llama 3 형식으로 바꾼다. 글자 수는 크게 늘었는데 토큰 수는 조금만 늘었다. 왜 그런가?
  3. Gemma 형식으로 바꾸면 시스템 지시문은 어디로 가는가? 이번에는 “＋ 사용자”를 두 번 눌러 사용자 메시지가 연달아 오게 한다. 무슨 경고가 나오는가?
  4. 마지막 어시스턴트 메시지를 지우고 “생성 프롬프트 붙이기”를 켠다. 문자열의 끝은 무엇인가? 모델은 어떤 토큰을 내면 멈추는가?
  5. 🧪 베이스 모델 사례와 ⚠ 템플릿 불일치 사례를 차례로 연다. 두 경우 모두 “모델이 멍청해서”가 아니다. 각각 무엇이 빠졌거나 어긋났는가?
  6. “템플릿 없음”을 고른다. 학습 비율은 몇 %인가? 이 데이터로 SFT하면 모델은 무엇까지 배우게 되는가?

4-2. LoRA 계산기

모델, rank r, LoRA를 붙일 층, 동결 가중치 정밀도를 고르면 학습 파라미터 수와 학습 메모리(가중치 + 기울기 + Adam 상태)를 계산한다. 막대의 세로선이 GPU 메모리다. 활성값은 빠진 추정치이고, 1GB = 109바이트로 계산한다.

관찰 질문

  1. 처음 설정(8B급, r = 16, 모든 층, bf16, 24GB)에서 전체 미세조정과 LoRA의 메모리를 기록한다. LoRA 막대에서 회색(동결 가중치)과 초록(학습 부분)의 비율은 어떤가?
  2. 정밀도를 fp32로 바꾼다. 학습 파라미터는 그대로인데 왜 24GB를 넘는가? 그다음 “8B QLoRA 4비트”를 누른다. 얼마로 줄었는가?
  3. r을 1 → 16 → 128로 옮기며 LoRA 비율과 메모리를 기록한다. 메모리는 r에 비례해 늘어나는가?
  4. “미니 GPT r = 32”를 누른다. 표에서 빨간 줄은 무엇을 뜻하는가? 미니 GPT에 LoRA를 쓰는 것이 이득인가?

C5. LoRA를 직접 학습시키기★★★★

6×6 가중치 W를 동결하고, 정답 W + ΔW*(rank 2)를 흉내 내도록 A와 B만 경사하강법으로 학습한다. 순전파 h = W·x + (α/r)·B·(A·x)와 기울기 두 줄, 갱신 두 줄을 채운다. 확인할 것: ① 시작 시점 출력 차이가 0인가(B = 0) ② 첫 단계에서 A의 기울기가 0인 이유 ③ W가 끝까지 그대로인가 ④ r = 1과 r = 2의 최종 손실 차이. 기대 결과: r = 2는 손실이 0에 가까워지고, r = 1은 0.54 근처에서 멈춘다.

import { mulberry32, gaussian } from '/assets/js/core/rng.js';
const rand = mulberry32(10);
const D = 6, N = 32;
const randMat = (rows, cols, std) => Array.from({ length: rows }, () => Array.from({ length: cols }, () => gaussian(rand) * std));
const matVec = (M, x) => M.map((row) => row.reduce((s, w, j) => s + w * x[j], 0));

// 동결된 사전학습 가중치 W, 그리고 새 과제의 정답 W + ΔW* (ΔW*는 rank 2)
const W = randMat(D, D, 0.5);
const u = randMat(2, D, 1), v = randMat(2, D, 1);
const dW = W.map((row, i) => row.map((_, j) => 0.6 * u[0][i] * v[0][j] + 0.3 * u[1][i] * v[1][j]));
const X = randMat(N, D, 1);
const Y = X.map((x) => matVec(W.map((row, i) => row.map((w, j) => w + dW[i][j])), x));

function train(r, steps = 400, lr = 0.02) {
  const alpha = r; // α = r → 배율 α/r = 1 (실전에서는 α를 고정해 두고 r을 바꾼다)
  const s = alpha / r;
  const A = randMat(r, D, 0.3);                                    // A: 작은 무작위 값
  const B = Array.from({ length: D }, () => new Array(r).fill(0)); // B: 0으로 시작
  const W0 = JSON.stringify(W);
  const forward = (x) => {
    const ax = matVec(A, x);
    // TODO: bax = B·(A·x)를 계산한다 (지금은 0으로 둔 자리표시)
    const bax = new Array(D).fill(0);
    return { ax, y: matVec(W, x).map((wx, i) => wx + s * bax[i]) };
  };
  const log = [];
  // 시작 시점: 모든 입력에서 LoRA 출력과 원래 모델 출력의 최대 차이
  const diff0 = Math.max(...X.map((x) => Math.max(...forward(x).y.map((y, i) => Math.abs(y - matVec(W, x)[i])))));
  for (let step = 0; step <= steps; step++) {
    const gA = randMat(r, D, 0), gB = randMat(D, r, 0); // 0으로 채운 기울기
    let loss = 0;
    X.forEach((x, n) => {
      const { ax, y } = forward(x);
      const dy = y.map((yi, i) => (2 * (yi - Y[n][i])) / N); // ∂loss/∂y
      loss += y.reduce((acc, yi, i) => acc + (yi - Y[n][i]) ** 2, 0) / N;
      // TODO: gB[i][k] += s · dy[i] · ax[k]
      // TODO: gA[k][j] += s · (Bᵀ·dy)[k] · x[j]   ((Bᵀ·dy)[k] = Σᵢ B[i][k]·dy[i])
    });
    if (step === 0) log.push({ step, loss: loss.toPrecision(4), '|gA|': +Math.hypot(...gA.flat()).toFixed(4), '|gB|': +Math.hypot(...gB.flat()).toFixed(4) });
    else if ([1, 10, 50, 100, 200, 400].includes(step)) log.push({ step, loss: loss.toPrecision(4) });
    // TODO: A와 B만 경사하강법으로 갱신한다: A[k][j] -= lr · gA[k][j], B[i][k] -= lr · gB[i][k]
  }
  return { diff0, log, frozen: JSON.stringify(W) === W0, trainable: r * (D + D) };
}

for (const r of [1, 2]) {
  const res = train(r);
  console.log(`r = ${r} · 학습 파라미터 ${res.trainable}개 (W는 ${D * D}개) · 시작 출력 차이 ${res.diff0} · W 그대로: ${res.frozen}`);
  console.table(res.log);
}

6정리 & 다음 주 예고

  • LLM은 사전학습 → 지시 미세조정(SFT) → 선호 학습(RLHF·DPO) 순서로 만들어진다. 구조는 같고, 데이터와 손실이 달라진다.
  • SFT는 대화를 채팅 템플릿으로 문자열 하나로 만들고, 어시스턴트의 답과 끝 토큰에서만 교차 엔트로피를 계산한다(나머지 정답은 −100).
  • 템플릿이 없으면 베이스 모델처럼 이어 쓰고, 학습과 추론의 템플릿이 다르면 멈춤 토큰이 어긋나 혼자 묻고 혼자 답한다.
  • 선호 학습은 “답 두 개 중 나은 쪽”을 데이터로 쓴다. RLHF는 보상 모델과 강화학습, DPO는 로지스틱 손실 하나로 한다.
  • 전체 미세조정은 파라미터당 약 16바이트(8B급 128.5GB)다. LoRA는 W를 동결하고 r × (din + dout)개만 학습하며, QLoRA는 동결 가중치까지 4비트로 줄인다.

다음 주(11주차 LLM API와 프롬프트)에는 직접 학습시키는 대신 이미 SFT와 선호 학습을 마친 LLM을 API로 불러 쓴다. API에 보내는 messages 목록이 바로 이번 주의 대화 구조이고, 채팅 템플릿은 서버가 대신 적용한다. 시스템 프롬프트, 구조화 출력, 도구 호출을 실습한다.
