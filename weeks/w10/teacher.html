코퍼스의 “사전학습과 미세조정” 문서(llm-training)가 이 표를 한 문단씩 설명한다. C1에서 이 문서의 첫 문장을 모범 답으로 쓴다.

강조: SFT의 손실은 4주차 교차 엔트로피와 완전히 같다. 새 수학이 없다. 바뀌는 것은 데이터 모양과 “어디서 손실을 계산하느냐”다.

채팅 템플릿: 대화 → 문자열 하나

<|im_start|>system
너는 AI응용소프트웨어과 학생을 돕는 조교다. …<|im_end|>
<|im_start|>user
실습실은 몇 시까지 이용할 수 있어?<|im_end|>
<|im_start|>assistant
평일에는 오후 9시까지 이용할 수 있다. …<|im_end|>
  • <|im_start|> = 글자 12개가 아니라 특수 토큰 1개
  • 형식은 모델마다 다르다: ChatML · Llama 3 (<|eot_id|>) · Gemma (<end_of_turn>, system 없음)
  • 추론: 끝에 <|im_start|>assistant↵만 붙이고 모델이 이어 쓴다

슬라이드의 형식은 간략화한 것이다. 실제 템플릿에는 도구 호출, 기본 시스템 문구 등이 붙는다. 실무에서는 토크나이저 설정 파일의 chat_template을 그대로 쓰라고 안내한다(직접 문자열을 만들지 않는다).

발문: “사용자가 채팅창에 <|im_end|>라고 직접 치면 어떻게 될까?” → 토크나이저가 일반 글자로 쪼개야 안전하다. 그렇지 않으면 대화 구조를 조작할 수 있다(프롬프트 주입의 한 형태).

146토큰 중 52토큰(35.6%)만 손실에 들어간다

토큰은 미니 GPT처럼 글자 1개 = 1토큰, 특수 토큰도 1개로 센 값이다. 실제 BPE 토크나이저로 세면 숫자는 달라지지만 비율의 의미는 같다.

발문: “질문까지 학습하면 뭐가 나쁠까?” → 모델이 사용자처럼 질문을 지어내는 법을 배운다. 질문은 추론 때 주어지므로 예측할 필요가 없다.

끝 토큰을 학습하지 않으면 모델이 답을 마치고도 멈추지 않는다. 데모의 템플릿 불일치 사례와 연결된다.

템플릿과 마스크, 코드 15줄

const msgs = [
  { role: 'system', content: '너는 학과 조교다.' },
  { role: 'user', content: '실습실은 몇 시까지 열어?' },
  { role: 'assistant', content: '평일 오후 9시까지다.' },
];
let text = '';
let mask = '';
for (const m of msgs) {
  const head = `<|im_start|>${m.role}\n`;
  const body = `${m.content}<|im_end|>`;
  text += head + body + '\n';
  mask += '0'.repeat([...head].length) + (m.role === 'assistant' ? '1' : '0').repeat([...body].length) + '0';
}
console.log(text);
console.log(mask);
console.log(`학습 글자 ${mask.split('1').length - 1} / 전체 ${mask.length} (글자 단위로 센 값)`);

실행 결과: 마스크 줄 끝부분에만 1이 22개 나온다. “학습 글자 22 / 전체 127”. 여기서는 특수 토큰도 글자 단위로 셌다(위젯과 C2는 특수 토큰을 1개로 센다). 세는 단위가 달라도 “답과 끝 표시만 1”이라는 구조는 같다.

시스템 메시지를 지우거나 assistant 차례를 하나 더 넣고 다시 실행해 본다.

선호 학습: “둘 중 어느 쪽이 나은가”

RLHF

  • 선호 쌍으로 보상 모델을 학습
  • 보상이 커지게 강화학습(PPO 등), SFT 모델에서 멀어지면 벌점

DPO

  • 보상 모델 없이 선호 쌍으로 바로
  • loss = −log σ(β[Δ고른 답 − Δ버린 답])
β = 0.1Δ고른 답Δ버린 답loss
시작000.693
옳은 방향+2−30.474
반대 방향−2+30.974

Δ는 “학습 중인 모델의 로그 확률 − 기준(SFT) 모델의 로그 확률”이다. 표의 loss는 −log σ(0.1 × (Δw − Δl))을 계산한 값이다.

핵심: 좋은 답을 사람이 새로 쓰는 것(SFT)보다 두 답 중 고르는 것(선호 데이터)이 훨씬 싸다. DPO 손실은 MLBasic의 로지스틱 회귀 손실과 같은 모양이다.

시간이 부족하면 RLHF의 PPO 세부는 생략하고 “보상 모델이 있다/없다”만 대비시킨다.

전체 미세조정: 파라미터당 16바이트

항목바이트
fp16/bf16 가중치 + 기울기2 + 2
fp32 가중치 원본4
Adam m + v (fp32)4 + 4
합계16

8B급 (8,030,261,248개) × 16 = 128.5GB → 24GB GPU 6장 분량 (활성값 제외)

16바이트는 혼합 정밀도 + AdamW의 어림셈이다. 옵티마이저, 정밀도, 샤딩 방식에 따라 달라진다고 말해 둔다.

9주차 메모리 계산기의 “추론 메모리”(bf16이면 16.1GB)와 비교하면 학습이 8배쯤 무겁다.

LoRA: W는 얼리고, B·A만 학습

h = W·x + (α/r)·B·(A·x)      A: r × d_in (무작위) · B: d_out × r (0에서 시작)
LoRA 파라미터 = r × (d_in + d_out)
  • 4096×4096 층, r = 16: 131,072개 = 0.78%
  • 8B급 모든 선형층 r = 16: 41,943,040개 = 0.52%
  • B = 0 → 학습 시작 때 출력이 원래 모델과 똑같다
  • 메모리: 동결 W (bf16 16.1GB) + 학습 0.67GB ≈ 16.7GB · QLoRA(4비트) ≈ 6.3GB

발문: “학습 파라미터가 0.5%인데 메모리는 왜 8분의 1밖에 안 줄었나?” → 동결 가중치는 여전히 GPU에 있어야 한다. 16.7GB 중 96%가 동결 가중치다(C4). 그래서 QLoRA는 그 동결 가중치를 4비트로 줄인다.

QLoRA 계산은 선형층만 4비트, 임베딩·출력층은 16비트로 둔 어림셈이다. 양자화 상수와 활성값은 뺐다.

학습 후 W + (α/r)·B·A를 합치면 추론 비용이 늘지 않는다. 합치지 않고 어댑터만 따로 저장하면(bf16 기준 약 84MB) 과제별로 바꿔 끼울 수 있다.

데모 · LoRA 계산기

시연 순서

  1. 처음 화면(8B급, r = 16, 모든 층, bf16, 24GB): 전체 미세조정 128GB ✗, LoRA 16.7GB ✓
  2. 정밀도 fp32 → LoRA 32.8GB ✗. 학습 파라미터는 그대로인데 넘친다 = 동결 가중치 탓
  3. “8B QLoRA 4비트” → 6.3GB
  4. r 1 → 128: 학습 부분 0.04GB → 5.4GB. r = 128이어도 21.4GB로 여전히 동결 가중치가 대부분
  5. “미니 GPT r = 32” → 빨간 줄: 48×48 층에 LoRA 3,072개 > 원래 2,304개. 작은 모델에는 LoRA가 이득이 아니다
  6. GPU 80GB로 바꿔도 전체 미세조정 128GB ✗

r을 바꾸면 얼마나 달라지나

// LoRA trainable parameters for an 8B-class model: r · (d_in + d_out) per linear layer
const layers = { q: [4096, 4096], k: [4096, 1024], v: [4096, 1024], o: [4096, 4096], gate: [4096, 14336], up: [4096, 14336], down: [14336, 4096] };
const L = 32, TOTAL = 8030261248;
for (const r of [1, 8, 16, 64]) {
  let lora = 0;
  for (const [dIn, dOut] of Object.values(layers)) lora += r * (dIn + dOut) * L;
  console.log(`r=${r}: ${lora.toLocaleString()}개 (${((lora / TOTAL) * 100).toFixed(2)}%) · 학습 부분 메모리 ${((lora * 16) / 1e9).toFixed(2)}GB`);
}
console.log(`전체 미세조정: ${TOTAL.toLocaleString()}개 × 16바이트 = ${((TOTAL * 16) / 1e9).toFixed(1)}GB`);
console.log(`LoRA의 동결 가중치(bf16): ${((TOTAL * 2) / 1e9).toFixed(1)}GB`);

실행 결과: r=1: 2,621,440개(0.03%) · 0.04GB / r=8: 20,971,520개(0.26%) · 0.34GB / r=16: 41,943,040개(0.52%) · 0.67GB / r=64: 167,772,160개(2.09%) · 2.68GB. 전체 미세조정 128.5GB, 동결 가중치(bf16) 16.1GB.

r을 64배 늘려도 학습 부분은 2.7GB다. 메모리를 지배하는 것은 동결 가중치라는 점을 다시 확인한다.

정리

  • 사전학습 → SFT → 선호 학습: 구조는 같고 데이터와 손실이 다르다
  • SFT = 채팅 템플릿 문자열 + 답과 끝 토큰에서만 교차 엔트로피
  • 템플릿 없음 → 이어 쓰기 · 템플릿 불일치 → 멈추지 못한다
  • 전체 미세조정 ≈ 16바이트/파라미터 · LoRA = r(d_in + d_out) · QLoRA = 동결 가중치 4비트
  • 새 지식은 미세조정보다 RAG가 먼저 (RAG 1주차)

const SPECIAL = ['<|im_start|>', '<|im_end|>'];

function tokenize(text) {
  const tokens = [];
  for (const part of text.split(/(<\|im_start\|>|<\|im_end\|>)/)) {
    if (SPECIAL.includes(part)) tokens.push(part);
    else tokens.push(...part); // one token per character
  }
  return tokens;
}

function lossMask(tokens) {
  const mask = [];
  let role = null;      // role of the current turn
  let inHeader = false; // between <|im_start|> and the first \n
  for (const t of tokens) {
    if (t === '<|im_start|>') { inHeader = true; role = ''; mask.push(0); continue; }
    if (inHeader) {
      if (t === '\n') inHeader = false;
      else role += t;
      mask.push(0);
      continue;
    }
    if (t === '<|im_end|>') { mask.push(role === 'assistant' ? 1 : 0); role = null; continue; }
    mask.push(role === 'assistant' ? 1 : 0);
  }
  return mask;
}

import { mulberry32, gaussian } from '/assets/js/core/rng.js';
const rand = mulberry32(10);
const D = 6, N = 32;
const randMat = (rows, cols, std) => Array.from({ length: rows }, () => Array.from({ length: cols }, () => gaussian(rand) * std));
const matVec = (M, x) => M.map((row) => row.reduce((s, w, j) => s + w * x[j], 0));

// 동결된 사전학습 가중치 W, 그리고 새 과제의 정답 W + ΔW* (ΔW*는 rank 2)
const W = randMat(D, D, 0.5);
const u = randMat(2, D, 1), v = randMat(2, D, 1);
const dW = W.map((row, i) => row.map((_, j) => 0.6 * u[0][i] * v[0][j] + 0.3 * u[1][i] * v[1][j]));
const X = randMat(N, D, 1);
const Y = X.map((x) => matVec(W.map((row, i) => row.map((w, j) => w + dW[i][j])), x));

function train(r, steps = 400, lr = 0.02) {
  const alpha = r; // α = r → 배율 α/r = 1 (실전에서는 α를 고정해 두고 r을 바꾼다)
  const s = alpha / r;
  const A = randMat(r, D, 0.3);                                    // A: 작은 무작위 값
  const B = Array.from({ length: D }, () => new Array(r).fill(0)); // B: 0으로 시작
  const W0 = JSON.stringify(W);
  const forward = (x) => {
    const ax = matVec(A, x);
    const bax = matVec(B, ax);
    return { ax, y: matVec(W, x).map((wx, i) => wx + s * bax[i]) };
  };
  const log = [];
  // 시작 시점: 모든 입력에서 LoRA 출력과 원래 모델 출력의 최대 차이
  const diff0 = Math.max(...X.map((x) => Math.max(...forward(x).y.map((y, i) => Math.abs(y - matVec(W, x)[i])))));
  for (let step = 0; step <= steps; step++) {
    const gA = randMat(r, D, 0), gB = randMat(D, r, 0); // 0으로 채운 기울기
    let loss = 0;
    X.forEach((x, n) => {
      const { ax, y } = forward(x);
      const dy = y.map((yi, i) => (2 * (yi - Y[n][i])) / N); // ∂loss/∂y
      loss += y.reduce((acc, yi, i) => acc + (yi - Y[n][i]) ** 2, 0) / N;
      for (let i = 0; i < D; i++) for (let k = 0; k < r; k++) gB[i][k] += s * dy[i] * ax[k];
      for (let k = 0; k < r; k++) {
        const btdy = B.reduce((acc, row, i) => acc + row[k] * dy[i], 0); // (Bᵀ·dy)[k]
        for (let j = 0; j < D; j++) gA[k][j] += s * btdy * x[j];
      }
    });
    if (step === 0) log.push({ step, loss: loss.toPrecision(4), '|gA|': +Math.hypot(...gA.flat()).toFixed(4), '|gB|': +Math.hypot(...gB.flat()).toFixed(4) });
    else if ([1, 10, 50, 100, 200, 400].includes(step)) log.push({ step, loss: loss.toPrecision(4) });
    for (let k = 0; k < r; k++) for (let j = 0; j < D; j++) A[k][j] -= lr * gA[k][j];
    for (let i = 0; i < D; i++) for (let k = 0; k < r; k++) B[i][k] -= lr * gB[i][k];
  }
  return { diff0, log, frozen: JSON.stringify(W) === W0, trainable: r * (D + D) };
}

for (const r of [1, 2]) {
  const res = train(r);
  console.log(`r = ${r} · 학습 파라미터 ${res.trainable}개 (W는 ${D * D}개) · 시작 출력 차이 ${res.diff0} · W 그대로: ${res.frozen}`);
  console.table(res.log);
}
