글자와 단어 사이, 토큰을 직접 만든다

지난주 모델은 글자 하나를 토큰 하나로 썼다. 그러면 문장이 너무 길어진다. 단어 하나를 토큰 하나로 쓰면 처음 보는 단어를 읽지 못한다. GPT가 쓰는 BPE는 “가장 자주 붙어 나오는 두 조각을 합친다”를 반복해 그 사이의 단위를 스스로 찾는다. 이번 주는 BPE를 처음부터 학습시키고, 한국어가 왜 토큰을 더 많이 쓰는지 바이트 단위로 확인한다.

1학습 목표

이번 주가 끝나면
  • 글자와 단어가 모두 좋은 토큰 단위가 아닌 이유를 어휘 크기와 문장 길이의 맞바꿈, 처음 보는 단어 문제로 설명할 수 있다.
  • BPE 학습(쌍 세기 → 가장 많은 쌍 합치기 → 반복)과 병합 순위에 따른 인코딩을 코드로 구현할 수 있다.
  • 바이트 단위 BPE가 무엇이고, 영어 중심 어휘에서 한국어가 왜 더 많은 토큰으로 쪼개지는지 설명할 수 있다.

2왜 필요한가

1주차의 바이그램은 글자 하나를 토큰 하나로 썼다. 어휘(vocabulary)는 495개로 작지만 코퍼스 6,828자가 그대로 6,828토큰이다. 모델이 한 번에 볼 수 있는 토큰 수는 정해져 있으므로, 토큰이 짧으면 같은 창에 들어가는 글이 적고 계산은 길어진다. “모델”이라는 단어도 모델은 “모”와 “델”을 따로 보고 둘이 붙어 다닌다는 사실을 매번 새로 배워야 한다.

반대로 띄어쓰기 단위인 어절 하나를 토큰 하나로 쓰면 어떨까? 코퍼스의 1,614어절은 서로 다른 1,107종이고 그중 846종이 딱 한 번만 나온다. 한국어는 조사와 어미가 붙기 때문에 “토큰”만 해도 “토큰을”, “토큰이”, “토큰으로”, “토큰의”처럼 13가지 어절로 나온다. 더 큰 문제는 처음 보는 단어다. “벡터 데이터베이스와 인덱스” 문서를 빼고 어휘를 만든 뒤 그 문서를 읽히면 78어절 중 51어절(65%)이 어휘에 없다. 어휘에 없는 단어는 모두 [UNK](unknown) 하나로 뭉개진다.

이번 주의 질문

어휘는 너무 크지 않고, 문장은 너무 길지 않고, 처음 보는 단어도 표현할 수 있는 토큰 단위가 있을까? — 자주 나오는 조각은 크게, 드문 조각은 작게 자르면 된다. 그 조각을 데이터에서 찾아 주는 방법이 BPE다.

3개념

토큰 단위의 스펙트럼

토크나이저(tokenizer)는 텍스트를 토큰으로 자르고 각 토큰에 번호를 붙인다. 어떤 단위로 자르느냐에 따라 어휘 크기와 토큰 수가 반대 방향으로 움직인다. 아래는 이 과정 코퍼스(17문서, 6,828자) 전체에 실제로 적용한 결과다.

토큰 단위어휘 크기코퍼스 토큰 수문제
글자4946,763문장이 길다. “모델”을 매번 두 조각으로 본다
BPE 병합 100회5945,085—
BPE 병합 400회8943,738늦게 배운 병합은 한두 문서의 어절을 통째로 외운다
어절(띄어쓰기)1,1071,614어휘의 76%가 한 번만 나온다. 새 문서 어절의 65%가 [UNK]

글자 단위의 토큰 수가 6,828이 아니라 6,763인 이유는 공백을 따로 세지 않고 “▁”로 단어 앞에 붙였기 때문이다(아래 “단어 경계” 참고). BPE는 이 표의 위아래 사이 어디든 원하는 곳에 멈출 수 있다. 병합 횟수가 곧 “어휘를 얼마나 키울 것인가”라는 손잡이다.

BPE 학습: 세고, 합치고, 반복한다

BPE(Byte Pair Encoding)는 원래 데이터 압축 기법이었다. 토크나이저로 쓸 때의 규칙은 세 줄이다.

  1. 모든 단어를 글자 단위로 쪼갠다. 처음 어휘 = 등장한 글자 전부.
  2. 학습 텍스트 전체에서 인접한 두 토큰 쌍이 몇 번 나오는지 센다.
  3. 가장 많이 나온 쌍 하나를 새 토큰으로 합쳐 어휘에 추가하고, 텍스트의 그 쌍을 모두 바꾼다. 2로 돌아간다.

우리 코퍼스로 학습하면 첫 병합은 “다 + .”(157번)이다. 한국어 문장 대부분이 “~다.”로 끝나기 때문이다. 이어서 “▁토”, “▁문”, “▁토큰”, “▁모”, “이다.”, “한다.”가 나온다. 사람이 정해 주지 않았는데도 어미와 자주 쓰는 단어가 먼저 토큰이 된다.

단어 경계: ▁와 사전 토큰화

BPE는 보통 먼저 공백으로 단어를 나눈 뒤(사전 토큰화, pre-tokenization) 단어 안에서만 쌍을 센다. 그래서 병합이 단어 경계를 넘지 않는다. 이 과정의 bpe.js는 SentencePiece처럼 단어 앞의 공백을 “▁” 기호로 단어에 붙인다. “▁토큰”은 단어 맨 앞의 “토큰”이고, 그냥 “토큰”은 “…의토큰”처럼 단어 중간에 나온 것이다. ▁ 덕분에 토큰을 이어 붙인 뒤 ▁를 공백으로 바꾸면 원문이 그대로 돌아온다(디코딩).

인코딩: 배운 순서대로 합친다

새 문장을 자를 때는 학습 때 배운 병합을 배운 순서(병합 순위, merge rank)대로 적용한다. 단어를 글자로 쪼갠 뒤, 인접 쌍 중 순위가 가장 높은(가장 먼저 배운) 쌍을 합치고, 합칠 쌍이 없을 때까지 반복한다. 학습 때와 같은 순서로 합쳐야 학습 때와 같은 조각이 나온다.

“벡터스토어는” (학습에 없던 어절, 병합 200회 어휘)
▁ 벡 터 스 토 어 는
→ ▁벡 터 스 토 어 는     20번째로 배운 병합 ▁+벡 (가능한 쌍 중 순위가 가장 높다)
→ ▁벡터 스 토 어 는      24번째로 배운 병합 ▁벡+터
→ 남은 쌍(터스, 스토, 토어, 어는)은 병합 목록에 없다 → 5토큰

처음 보는 단어라도 [UNK]가 되지 않는다. 아는 조각(“▁벡터”)은 크게, 모르는 부분은 글자 단위로 작게 잘린다. 이것이 BPE를 서브워드(subword) 토크나이저라고 부르는 이유다. 단, 학습 텍스트에 없던 글자(예: “챗”, “봇”)는 글자 단위 어휘에도 없다. 여전히 [UNK]다.

바이트 단위 BPE: 어떤 글자든 표현한다

GPT-2 이후 GPT 계열은 글자가 아니라 UTF-8 바이트에서 BPE를 시작한다. 바이트는 256종뿐이므로 처음 어휘가 256개로 고정되고, 이모지든 처음 보는 한자든 어떤 글자도 바이트로 쪼개 표현할 수 있다. [UNK]가 사라진다. 대가는 길이다. UTF-8에서 영어 알파벳은 1바이트지만 한글 음절은 3바이트다.

우리 코퍼스를 바이트로 쪼개면 처음 어휘는 135종(실제 토크나이저는 256종 전부를 넣는다), 토큰 수는 15,645개로 글자 단위(6,763)의 2.3배다. 첫 병합들은 “▁<EC>”, “▁<EB>”, “<EC><9D>”처럼 한글 음절의 일부다. 음절 하나가 온전한 토큰이 되려면 병합이 두 번 필요하다. 병합 400회 뒤에도 5,476토큰으로 글자 단위 BPE 400회(3,738)보다 많다.

영어 중심 어휘에서 한국어가 비싼 이유

GPT-2의 어휘(50,257개)는 영어 웹 문서로 병합을 배웠다. 영어 단어는 통째로 토큰이 되었지만 한글 바이트 조합은 거의 병합되지 않았다. 그래서 한글 음절 하나가 토큰 2~3개로 쪼개진다. 이것은 한국어가 원래 어려워서가 아니라 어휘를 만든 데이터에 한국어가 적었기 때문이다. 반대로 우리 코퍼스(대부분 한국어)로 만든 어휘는 영어 문장 “Tokenizers split rare words into pieces.”를 병합 400회 뒤에도 40자 → 39토큰(바이트 단위는 41토큰)으로 거의 글자마다 자른다. 같은 현상의 거울상이다.

4실습

학습 텍스트와 시작 단위를 고르면 그 자리에서 BPE를 400회까지 학습한다(처음 한 번만 1초쯤 걸리고 이후는 즉시). 병합 횟수 슬라이더나 ◀ ▶로 한 단계씩 움직이며 결과를 오른쪽 실행 결과 창에서 본다(휴대폰에서는 위젯 바로 아래). 테스트 문장은 직접 고쳐 쓸 수 있다. 빨간 상자는 어휘에 없는 글자, 점선 노란 상자는 음절이 깨진 바이트 조각이다.

관찰 질문

  1. “0회” 버튼을 누른 뒤 “한 단계 ▶”를 다섯 번 누른다. 처음 병합되는 쌍은 무엇이고, 왜 하필 그 쌍인가? 한국어 문장이 어떻게 끝나는지 떠올린다.
  2. 테스트 문장을 “처음 보는 문장”으로 두고 병합을 0 → 100 → 400회로 바꾼다. 27자 문장의 토큰 수는 28 → 24 → 23으로 거의 줄지 않는다. “메타버스”는 어떻게 잘리는가? 빨간 “챗”, “봇”은 왜 생겼는가?
  3. 시작 단위를 “UTF-8 바이트”로 바꾼다. 빨간 상자가 사라진 대신 무엇이 생겼는가? 같은 문장이 병합 0회에서 몇 토큰인가(글자 단위와 비교)? 병합 100회, 400회에서는?
  4. ▶ 재생을 누르고 그래프와 “새로 배운 병합”의 ×횟수를 본다. 병합이 늘수록 한 번 병합으로 줄어드는 토큰 수는 어떻게 변하는가? 400회 근처에서 합쳐지는 토큰은 어떤 모양인가?
  5. 학습 텍스트를 “실습실 이용 규정 한 편”으로 바꾸고 400회를 누른다. 글자 단위는 몇 회에서 멈추는가? 왜 더 합칠 수 없는가? 마지막으로 테스트 문장을 “영어 문장”으로 바꿔 코퍼스 전체 400회에서 몇 토큰인지 보고, RAG 1주차의 GPT-2 한국어 결과와 비교한다.

C2. 병합 한 단계★

단어의 토큰 배열에서 (a, b) 쌍을 찾아 a+b 하나로 바꾸는 mergeWord를 구현한다. 그러면 준비된 반복문이 가장 많은 쌍을 세 번 합친다. 기대 결과: 전체 토큰 59 → 49 → 41 → 35. 마지막 줄의 ['a','a','a']는 겹치는 쌍 검사다. 왼쪽부터 합치므로 ['aa','a']가 나와야 한다.

// each word is now a list of symbols; one merge rewrites these lists
let words = [
  { syms: [...'▁토큰'], count: 5 },
  { syms: [...'▁토큰을'], count: 3 },
  { syms: [...'▁토크나이저'], count: 2 },
  { syms: [...'▁모델'], count: 4 },
  { syms: [...'▁모델을'], count: 2 },
];
const total = (ws) => ws.reduce((s, w) => s + w.syms.length * w.count, 0);
const show = (ws) => ws.map((w) => `${w.syms.join(' ')} ×${w.count}`).join('  |  ');

function bestPair(words) {
  const pairs = new Map();
  for (const { syms, count } of words)
    for (let i = 0; i < syms.length - 1; i++) {
      const key = syms[i] + ' ' + syms[i + 1];
      pairs.set(key, (pairs.get(key) ?? 0) + count);
    }

  for (const [key, c] of pairs) if (c > bestCount) [best, bestCount] = [key, c];
  return { pair: best.split(' '), count: bestCount };
}

}

6정리 & 다음 주 예고

  • 토큰 단위는 어휘 크기와 문장 길이를 맞바꾼다. 글자는 어휘가 작고 문장이 길다. 어절은 문장이 짧지만 어휘가 크고 처음 보는 단어를 [UNK]로 뭉갠다.
  • BPE는 가장 자주 붙어 나오는 쌍을 합치기를 반복해 그 사이의 단위를 데이터에서 찾는다. 순서대로 기록한 병합 목록이 토크나이저다.
  • 인코딩은 배운 순서(병합 순위)대로 합친다. 처음 보는 단어는 아는 조각과 낱글자로 잘린다.
  • 바이트 단위 BPE는 256개 바이트에서 시작해 [UNK]가 없다. 한글 음절은 3바이트라, 한국어 병합을 적게 배운 영어 중심 어휘에서는 한국어가 토큰을 몇 배 더 쓴다.
