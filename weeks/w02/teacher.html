지난주: 토큰 = 글자 하나

  • 바이그램은 “모” 다음에 “델”이 온다는 것을 세어서 알았다
  • 코퍼스 6,828자 = 6,828토큰 · 어휘 495
  • “모델”은 매번 두 토큰. 모델이 “모델”을 한 덩어리로 알 수는 없을까?

토큰을 더 크게 자르면 어떻게 될까?

발문: “토큰을 단어로 하면 되지 않나?” 대부분 그렇게 답한다. 다음 슬라이드에서 그 답의 문제를 숫자로 보여 준다.

1주차 C5 과제 답(n = 2가 NLL 4.163으로 가장 좋음)을 먼저 짧게 확인한다.

오늘 할 수 있게 되는 것

  1. 글자도 단어도 좋은 토큰이 아닌 이유: 어휘 크기 ↔ 문장 길이, 처음 보는 단어
  2. BPE 학습(세기 → 합치기 → 반복)과 인코딩(병합 순위)을 코드로 쓴다
  3. 바이트 단위 BPE와 한국어가 토큰을 더 쓰는 이유를 설명한다

오늘 만든 토크나이저 개념은 3주차 임베딩(어휘 크기 = 임베딩 표의 행 수)과 RAG 과정의 토큰 비용 계산에서 다시 쓴다.

두 극단: 글자 vs 어절

단위어휘코퍼스 토큰문제
글자4946,763문장이 길다
어절1,1071,61476%가 한 번만 나옴 · 새 문서 어절 65%가 [UNK]

“토큰” 하나가 13가지 어절로: 토큰 · 토큰을 · 토큰이 · 토큰으로 · 토큰의 · 토큰만 …

새 문서 = 학습에서 뺀 “벡터 데이터베이스와 인덱스”(356자, 78어절). 51어절이 학습 텍스트에 없다. C5에서 학생이 직접 재현한다.

한국어는 교착어라 어절 단위 어휘가 특히 불리하다. 영어의 “token / tokens” 수준이 아니다.

글자 단위 토큰이 6,828이 아닌 6,763인 이유: 공백 1,679개 대신 단어 1,614개 앞에 ▁를 붙였기 때문(연속 공백·줄바꿈은 하나로).

BPE: 가장 자주 붙어 나오는 쌍을 합친다

단어와 횟수

▁ 토 큰        ×5
▁ 토 큰 을     ×3
▁ 토 크 나 이 저 ×2
▁ 모 델        ×4
▁ 모 델 을     ×2

병합 기록

  1. ▁ + 토 → ▁토 (×10) · 59 → 49
  2. ▁토 + 큰 → ▁토큰 (×8) · → 41
  3. ▁ + 모 → ▁모 (×6) · → 35

병합 한 번 = 어휘 +1, 토큰 −횟수

활동(10분): 짝과 함께 칠판의 단어로 인접 쌍을 모두 세게 한다(10종). 1등 쌍을 합친 뒤 다시 세면 “▁토 큰”이 8이 된다는 것을 스스로 발견하게 한다.

병합 3에서 “▁ 모”(6)와 “모 델”(6)이 동점이다. 동점 처리 규칙이 필요하다는 것을 짚는다(core는 사전순). C3의 “core와 같은 병합 50/50” 검사가 이 규칙에 달려 있다.

토큰 감소량 = 합친 쌍의 횟수(10, 8, 6)라는 점을 확인시킨다.

코퍼스로 학습하면

import { train, encode, showSymbol } from '/assets/js/core/bpe.js';
const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const text = corpus.documents.map((d) => d.text).join('\n\n');
const sentence = '토큰 수는 곧 비용이다.';
for (const unit of ['char', 'byte']) {
  for (const merges of [0, 100]) {
    const tok = train(text, { merges, unit });
    const toks = encode(tok, sentence).map((t) => showSymbol(t, unit));
    console.log(`${unit} · 병합 ${merges}회 · ${toks.length}토큰:`, toks.join(' | '));
  }
}
const tok = train(text, { merges: 10 });
console.log('처음 배운 병합 10개:', tok.merges.map((m) => `${m.a}+${m.b}(${m.count})`).join(' '));

실행 결과: 처음 배운 병합 10개 = 다+.(157) ▁+토(44) ▁+문(43) ▁토+큰(42) ▁+모(41) 이+다.(30) 한+다.(30) ▁+수(28) ▁+가(27) ▁+검(27).

“토큰 수는 곧 비용이다.” → 글자 0회 14토큰, 100회 8토큰(▁토큰 | ▁수 | 는 | ▁ | 곧 | ▁비 | 용 | 이다.) · 바이트 0회 32토큰, 100회 11토큰(▁<EC> | <88><98> 같은 조각이 남음).

발문: “첫 병합이 왜 ‘다 + .’일까?” → 한국어 문장이 “~다.”로 끝난다. 사람이 문법을 알려 주지 않아도 어미가 먼저 토큰이 된다.

새 단어 자르기: 배운 순서대로

“벡터스토어는” (학습에 없던 어절, 병합 200회)
▁ 벡 터 스 토 어 는
→ ▁벡 터 스 토 어 는     (20번째 병합 ▁+벡)
→ ▁벡터 스 토 어 는      (24번째 병합 ▁벡+터)
→ 더 합칠 쌍 없음 → 5토큰
  • 매번 순위가 가장 높은(먼저 배운) 쌍부터 합친다 = 학습 때와 같은 조각
  • 아는 조각은 크게, 모르는 부분은 낱글자로 → [UNK] 없음 (서브워드)
  • 디코딩: 이어 붙이고 ▁ → 공백

“왼쪽부터 아무 병합이나 적용하면 안 되나?” → 학습 때와 다른 조각이 나올 수 있다. 같은 단어가 늘 같은 토큰열이 되어야 모델이 배운 것을 쓸 수 있다.

단, 학습 텍스트에 없던 글자는 글자 단위 어휘에 없다 → 여전히 [UNK]. 데모에서 “챗”, “봇”으로 보여 준다. 이것이 바이트 단위로 가는 동기다.

데모 · BPE 병합 스텝퍼

시연 순서 (결과는 오른쪽 실행 결과 창)

  1. “0회” → 한 단계 ▶ 몇 번: 다+.(157), ▁+토(44) … 병합 목록이 위로 쌓인다
  2. ▶ 재생: 그래프 점이 오른쪽 아래로. 처음엔 한 번에 많이 줄고 나중엔 조금씩 준다
  3. 테스트 “처음 보는 문장”: 27자가 0회 28토큰, 400회에서도 23토큰. “메타버스”는 낱글자, “챗”·“봇”은 빨간 [UNK]
  4. UTF-8 바이트로 전환: 빨간 상자가 사라지고 노란 점선 조각(<EB><A9>…)이 생긴다. 0회 72토큰 → 100회 38토큰 → 400회 30토큰 (글자 단위보다 여전히 많다)
  5. 400회 근처의 병합(×3 “▁사용한다.”, “▁미세조정” 등): 어절을 통째로 외우기 시작
  6. “실습실 이용 규정 한 편” + 글자 단위: 30회에서 합칠 쌍이 바닥난다
  7. “영어 문장”: 400회에서도 40자 → 39토큰. “GPT-2가 한국어를 볼 때 이렇다”

바이트 단위 BPE: [UNK]가 없다

“토큰A”토큰
글자토 | 큰 | A → 3
UTF-8 바이트ED 86 A0 | ED 81 B0 | 41 → 7
  • 시작 어휘 = 바이트 256개 → 어떤 글자·이모지든 표현
  • 한글 음절 = 3바이트, 영어 = 1바이트
  • 우리 코퍼스: 바이트 15,645토큰 = 글자(6,763)의 2.3배 · 400회 병합 후 5,476

GPT-2 이후 GPT 계열 토크나이저가 모두 이 방식이다. 위젯의 바이트 모드 “어휘 크기”는 코퍼스에 실제로 나온 바이트 135종부터 센다. 실제 토크나이저는 256종 전부를 넣는다고 짚는다.

초기 병합(“▁<EC>” ×589, “▁<EB>” ×456, “<EC><9D>” ×370)은 음절의 앞부분이다. 한글은 첫 바이트가 EA~ED로 몰려 있어 이 조각들이 매우 흔하다.

GPT-2: 한국어 ≈ 영어의 4.6배 · GPT-4o: 약 1.2배 — 어휘를 만든 데이터의 차이

수치는 studyRAG 1주차 토큰 카운터의 실측값이다(RAG 1주차). GPT-2 어휘 50,257개는 영어 웹 문서로 병합을 배웠고, GPT-4o 어휘(약 20만 개)는 다국어 데이터로 배웠다.

거울상: 우리 코퍼스(한국어)로 만든 어휘는 영어 문장을 거의 글자마다 자른다(40자 → 39토큰). “한국어가 어려워서”가 아니라 “어휘가 한국어를 적게 봐서”다.

토큰 수 = 컨텍스트 창 사용량 = API 비용. RAG 과정에서 청크 크기를 토큰으로 정하는 이유.

어휘는 얼마나 커야 하나?

어휘를 키우면

  • 문장이 짧아진다 → 같은 창에 더 많은 글
  • 임베딩 표(V × d)가 커진다
  • 드문 토큰은 학습 예가 적다 (외우기)

실제 값

  • GPT-2: 50,257 × 768 ≈ 3,860만 파라미터
  • GPT-4o: 약 20만
  • 7주차 미니 GPT: 글자 495개

3주차 임베딩 예고. 어휘 크기 V가 임베딩 표의 행 수라는 점만 짚는다. GPT-2 small의 토큰 임베딩만 50,257 × 768 = 38,597,376개 파라미터다.

7주차 미니 GPT는 구현을 단순하게 하려고 글자 단위(어휘 495)를 쓴다. 대신 같은 글이 더 많은 토큰이 되어 문맥 창을 빨리 채운다.

정리

  • 토큰 단위 = 어휘 크기 ↔ 문장 길이의 맞바꿈
  • BPE 학습: 세기 → 1등 합치기 → 반복. 병합 목록이 곧 토크나이저
  • 인코딩은 병합 순위대로 · 처음 보는 단어는 조각과 낱글자로
  • 바이트 BPE: [UNK] 없음, 한글 = 3바이트 → 영어 중심 어휘에서 비싸다

// word → how many times it appears in the training text (▁ = the space before a word)
const words = { '▁토큰': 5, '▁토큰을': 3, '▁토크나이저': 2, '▁모델': 4, '▁모델을': 2 };

function countPairs(words) {
  const pairs = new Map();
  for (const [word, count] of Object.entries(words)) {
    const syms = [...word];
    for (let i = 0; i < syms.length - 1; i++) {
      const key = syms[i] + ' ' + syms[i + 1];
      pairs.set(key, (pairs.get(key) ?? 0) + count);
    }
  }
  return pairs;
}

function bestPair(words) {
  const pairs = new Map();
  for (const { syms, count } of words)
    for (let i = 0; i < syms.length - 1; i++) {
      const key = syms[i] + ' ' + syms[i + 1];
      pairs.set(key, (pairs.get(key) ?? 0) + count);
    }
  let best = null, bestCount = 0;
  for (const [key, c] of pairs) if (c > bestCount) [best, bestCount] = [key, c];
  return { pair: best.split(' '), count: bestCount };
}

function mergeWord(syms, a, b) {
  const out = [];
  for (let i = 0; i < syms.length; i++) {
    if (i < syms.length - 1 && syms[i] === a && syms[i + 1] === b) {
      out.push(a + b);
      i++; // skip b: it is now inside the merged symbol
    } else out.push(syms[i]);
  }
  return out;
}

  const merges = [];
  for (let step = 1; step <= numMerges; step++) {
    const pairs = new Map();
    for (const { syms, count } of words)
      for (let i = 0; i < syms.length - 1; i++) {
        const key = syms[i] + '\u0000' + syms[i + 1];
        pairs.set(key, (pairs.get(key) ?? 0) + count);
      }
    let best = null, bestCount = 0;
    for (const [key, c] of pairs) if (c > bestCount || (c === bestCount && key < best)) [best, bestCount] = [key, c];
    if (bestCount < 2) break; // a pair seen only once is not worth a vocabulary slot
    const [a, b] = best.split('\u0000');
    words = words.map((w) => ({ ...w, syms: mergeWord(w.syms, a, b) }));
    merges.push({ step, a, b, merged: a + b, count: bestCount, tokens: total() });
  }
  return merges;
}

function encodeWord(word) {
  let syms = [...word];
  for (;;) {
    let bestI = -1, bestR = Infinity;
    for (let i = 0; i < syms.length - 1; i++) {
      const r = rank.get(syms[i] + '\u0000' + syms[i + 1]);
      if (r !== undefined && r < bestR) [bestR, bestI] = [r, i];
    }
    if (bestI < 0) return syms; // no learned merge applies any more
    syms = [...syms.slice(0, bestI), syms[bestI] + syms[bestI + 1], ...syms.slice(bestI + 2)];
  }
}

const decode = (tokens) => tokens.join('').replaceAll('▁', ' ').trim();
