“실습실은 ___”

스마트폰 자판은 다음 단어를 어떻게 고를까?

  • 지금까지 친 글을 본다
  • 다음에 올 후보마다 확률을 매긴다
  • 가장 그럴듯한 것을 보여 준다

ChatGPT도 같은 일을 한다. 규모와 확률을 계산하는 방법만 다르다

발문: 학생들에게 “실습실은” 다음 단어를 말하게 하고 칠판에 적는다(개방, 본관, 평일…). 각자 머릿속에서 확률을 매긴 것이다.

“어떻게 그 단어를 떠올렸나?” → 비슷한 문장을 많이 봤기 때문 → 오늘은 그 “많이 봤다”를 직접 센다.

언어 모델 = 다음 토큰의 조건부 확률

P(다음 토큰 | 앞 토큰들)

P(실 습 실 은) = P(실) × P(습 | 실) × P(실 | 실 습) × P(은 | 실 습 실)
  • 문장의 확률 = 조건부 확률을 차례로 곱한 것 (연쇄 법칙)
  • 이번 주 토큰 = 글자 하나 (다음 주에 더 나은 단위)

연쇄 법칙은 근사가 아니라 항등식이다. 근사는 다음 슬라이드의 “앞 n−1개만 본다”에서 들어온다고 구분해 준다.

텍스트 분류 vs 언어 모델

MLBasic 텍스트 분류 (BoW)

  • “영화가 재미없다” ≈ “재미가 없는 영화다”
  • 순서를 버려도 된다
  • 출력: 긍정/부정

언어 모델

  • 글자를 섞으면 뜻이 사라진다
  • 순서가 전부
  • 출력: 다음 토큰의 분포

선수 과정 복습 슬라이드다. BoW를 기억 못 하는 학생이 있으면 “단어 개수 벡터”라고만 짚고 넘어간다.

바이그램: 바로 앞 글자 하나만 본다

습 77/21 = 33%확률만큼 무작위로 하나

학습 = 세기 · 예측 = 나누기 · 생성 = 뽑기의 반복 (자기회귀)

숫자는 이 과정 코퍼스(17문서, 6,828자)를 실제로 센 값이다. Challenge C2의 기대 결과와 같다.

발문: “왜 항상 1등(습)을 고르지 않고 무작위로 뽑나?” → 항상 1등이면 같은 글만 나온다. 8주차 디코딩 전략의 예고.

데모 · n-gram 언어 모델

시연 순서 (결과는 오른쪽 실행 결과 창)

  1. 처음 화면: n = 2. “모델”, “실습”은 맞고 문장은 엉뚱하다
  2. 빨간 글자 하나를 눌러 후보 막대를 보여 준다. “확률 낮은 것도 가끔 뽑힌다”
  3. 🎲 몇 번 → 매번 다른 글. seed가 같으면 같은 글
  4. n = 1 → 글자 수프. n = 3 → 단어가 자연스러워짐
  5. “n = 5 (외우기 재현)” → 복사율 84%, 평균 후보 1.3개. “이 모델은 언어를 배웠나, 문서를 외웠나?”
  6. n = 6 → 시작하자마자 막다른 길

“새 문서”는 학습에서 뺀 “벡터 데이터베이스와 인덱스” 문서(356자)다. NLL은 add-k(k = 0.1) 스무딩을 쓴 값이다. Challenge C5의 정답 표와 같다.

핵심: n을 키우면 학습 문서는 더 잘 맞히지만(외우기) 새 문서는 더 못 맞힌다(빈칸). 과대적합이다. “비슷한 문맥”을 알아보는 능력(일반화)이 없기 때문 → 3·4주차.

문장의 확률은 로그로 더한다

log P(문장) = Σ log P(xᵢ | xᵢ₋₁)
글자당 NLL = −log P(문장) / 글자 수
문장k = 0k = 0.1글자당 NLL
실습실은 평일 오후 9시까지 개방된다.−43.0−64.63.23
다개은 실9습 후평까오 …(섞음)−∞−110.55.52
실습실은 토요일 오전에도 개방된다.−∞−67.03.72

확률을 그대로 곱하면 10−19처럼 작아져 컴퓨터에서 0이 된다(언더플로). 그래서 로그를 더한다.

세 번째 문장은 말이 되는데도 k = 0이면 −∞다. “토요”, “요일”, “전에” 쌍이 코퍼스에 없기 때문. 스무딩은 “본 적 없다 ≠ 불가능하다”를 반영하는 응급 처치다.

글자당 NLL은 4주차 교차 엔트로피 손실과 같은 식이다. 미리 연결해 둔다.

바이그램 언어 모델, 코드 12줄

import { mulberry32 } from '/assets/js/core/rng.js';
const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const chars = [...corpus.documents.map((d) => d.text).join('\n\n')];
const table = new Map();                                  // ① 세기
for (let i = 0; i < chars.length - 1; i++) {
  const row = table.get(chars[i]) ?? new Map();
  row.set(chars[i + 1], (row.get(chars[i + 1]) ?? 0) + 1);
  table.set(chars[i], row);
}
const rand = mulberry32(7), out = [...'모델은'];
for (let i = 0; i < 50; i++) {                           // ②③ 나누고 뽑기
  const row = [...table.get(out.at(-1))];
  let r = rand() * row.reduce((s, [, c]) => s + c, 0);
  out.push(row.find(([, c]) => (r -= c) < 0)[0]);
}
console.log(out.join(''));

▶ 실행 후 seed(7)를 바꿔 다시 실행한다. 확률로 나누지 않고 “횟수 합 × rand”로 바로 뽑는 방법도 같은 결과라는 점을 짚는다(C3의 다른 풀이).

정리

  • 언어 모델 = 다음 토큰의 조건부 확률 분포, 생성 = 한 토큰씩 뽑아 붙이기
  • n-gram: 학습 = 세기, 예측 = 나누기
  • n이 크면 외우고, 새 문맥에서는 확률 0 → 일반화가 필요하다
  • 문장의 확률은 로그의 합 · 글자당 NLL은 곧 교차 엔트로피

function buildBigram(text) {
  const table = new Map(), chars = [...text];
  for (let i = 0; i < chars.length - 1; i++) {
    const row = table.get(chars[i]) ?? new Map();
    row.set(chars[i + 1], (row.get(chars[i + 1]) ?? 0) + 1);

  }

}

function sampleIndex(probs, rand) {
  const r = rand();
  let cum = 0;
  for (let i = 0; i < probs.length; i++) {
    cum += probs[i];
    if (r < cum) return i;
  }
  return probs.length - 1; // 부동소수점 오차 대비
}
const rand = mulberry32(42);
const hits = [0, 0, 0];
for (let i = 0; i < 10000; i++) hits[sampleIndex([0.5, 0.3, 0.2], rand)]++;
console.log('뽑힌 비율:', hits.map((h) => h / 10000));
function generate(start, length, seed) {
  const r = mulberry32(seed);
  const out = [...start];
  for (let i = 0; i < length; i++) {
    const row = table.get(out[out.length - 1]);
    if (!row) break; // 막다른 길
    const nexts = [...row.keys()];
    let total = 0;
    row.forEach((c) => (total += c));
    out.push(nexts[sampleIndex(nexts.map((n) => row.get(n) / total), r)]);
  }
  return out.join('');
}

const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const chars = [...corpus.documents.map((d) => d.text).join('\n\n')];
const V = new Set(chars).size;
const table = new Map();
for (let i = 0; i < chars.length - 1; i++) {
  const row = table.get(chars[i]) ?? new Map();
  row.set(chars[i + 1], (row.get(chars[i + 1]) ?? 0) + 1);
  table.set(chars[i], row);
}
function prob(prev, next, k) {
  const row = table.get(prev) ?? new Map();
  let total = 0;
  row.forEach((c) => (total += c));
  const denom = total + k * V;
  return denom === 0 ? 0 : ((row.get(next) ?? 0) + k) / denom;
}
function logProb(sentence, k) {
  const cs = [...sentence];
  let lp = 0;
  for (let i = 1; i < cs.length; i++) lp += Math.log(prob(cs[i - 1], cs[i], k));
  return lp;
}
const original = '실습실은 평일 오후 9시까지 개방된다.';
const shuffled = '다개은 실9습 후평까오 지된실일시 방.';
const unseen = '실습실은 토요일 오전에도 개방된다.';
console.table([original, shuffled, unseen].map((s) => ({
  s,
  'k=0': logProb(s, 0).toFixed(2),
  'k=0.1': logProb(s, 0.1).toFixed(2),
  '글자당 NLL(k=0.1)': (-logProb(s, 0.1) / ([...s].length - 1)).toFixed(3),
})));
const cs = [...unseen];
console.log('확률 0인 쌍:', cs.slice(1).map((c, i) => cs[i] + c).filter((p) => prob(p[0], p[1], 0) === 0));

해석: 스무딩을 넣으면 원문의 로그 확률도 낮아진다(−43 → −65). 본 적 있는 쌍의 확률을 떼어 본 적 없는 쌍에 나눠 주기 때문이다. 새 문장이 섞은 문장보다 훨씬 그럴듯하다고 판정하는 것은 스무딩 덕분이다.

import { countNgrams, nll } from '/assets/js/core/ngram.js';
const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const join = (docs) => docs.map((d) => d.text).join('\n\n');
const trainText = join(corpus.documents.filter((d) => d.id !== 'rag-vectordb'));
const valText = [...join(corpus.documents.filter((d) => d.id === 'rag-vectordb'))];
const rows = [];
for (let n = 1; n <= 5; n++) {
  const model = countNgrams([...trainText], n);
  rows.push({
    n,
    contexts: model.counts.size,
    zeros: nll(model, valText).zeros,
    nll: +nll(model, valText, { k: 0.1 }).nll.toFixed(3),
  });
}
console.table(rows);
const best = rows.reduce((a, b) => (b.nll < a.nll ? b : a));
console.log(`가장 좋은 n = ${best.n}. n이 커지면 가능한 문맥이 495^(n-1)로 늘어 새 문서의 문맥 대부분이 학습에 없다.`);
