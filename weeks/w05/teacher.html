이번 주가 과정 전체의 고비다. 수식보다 C1 표의 숫자 한 줄을 끝까지 따라가게 하는 것이 목표다. 행렬 곱이 흐린 학생이 많으면 슬라이드 7 앞에서 2×2 행렬 곱을 칠판에 한 번 한다.

4주차 모델의 두 벽

① 창이 고정되어 있다

  • 마지막 토큰 몇 개의 임베딩을 이어 붙인다
  • 창 밖은 보이지 않는다
  • 창을 넓히면 첫 층 가중치도 창 크기에 비례해 늘어난다

② 가중치가 자리에 묶여 있다

  • “바로 앞”용, “두 칸 앞”용 가중치가 따로
  • 같은 단어라도 자리가 바뀌면 다시 배워야 한다

필요한 것: 어디에 있든, 지금 중요한 토큰을 내용으로 찾아 가져오는 장치

4주차 위젯/코드에서 입력 벡터를 만들 때 임베딩을 concat했던 장면을 떠올리게 한다. “창을 10으로 넓히면 입력 차원이 몇 배가 되나?” → 창 크기 × D.

②는 합성곱 신경망을 배운 학생에게 “가중치 공유가 없는 상태”라고 설명하면 통한다.

오늘 할 수 있게 되는 것

  1. Q·K·V → QKᵀ → ÷√d → 인과 마스크 → 소프트맥스 → ·V를 단계별로 계산한다
  2. 마스크가 왜 필요한지, √d로 왜 나누는지 설명한다
  3. 멀티헤드 어텐션이 무엇을 나란히 계산하는지 설명한다

C5의 causalAttention은 7주차 미니 GPT 학습기가 실제로 쓰는 함수다. “오늘 만든 것이 7주차에 그대로 돌아간다”고 동기를 준다.

“실습실은 평일 오후 9시 ___”

빈칸을 채울 때 여러분은 앞의 어느 단어를 봤나?

  • “까지”를 떠올리려면 → 9시, 오후 (시간 표현)
  • “개방된다”까지 가려면 → 실습실은 (주어)
  • “은”, “평일”은 덜 중요하다

단어마다 “얼마나 볼지” 비율이 다르다 → 이 비율을 계산하는 것이 어텐션

발문: 학생에게 단어마다 0~100%로 “참고한 정도”를 매기게 하고 합이 100%가 되게 한다. 그 숫자가 곧 오늘 계산할 어텐션 가중치 한 행이다.

“자리(몇 칸 앞)가 아니라 내용(시간 표현인가)으로 골랐다”는 점을 짚는다.

쿼리 · 키 · 값 = 검색

만드는 법뜻도서관 비유
쿼리 qx · Wq나는 이런 정보를 찾는다검색어
키 kx · Wk나는 이런 정보를 갖고 있다책의 색인
값 vx · Wv실제로 건네줄 내용책의 내용

점수 = q · k (잘 맞을수록 큼) → 소프트맥스 → 그 비율로 v를 섞어 가져온다

검색과 다른 점: 1등 한 권만 가져오지 않고 비율대로 섞는다(“소프트” 검색). 그래서 미분 가능하고 학습할 수 있다.

RAG를 먼저 들은 학생에게는 “벡터 검색의 코사인 유사도 = 쿼리와 키의 내적”이라고 연결하면 빠르다.

쿼리 “9시” = [0.9, 1.2]의 한 행

키벡터q·k÷√2소프트맥스
실습실[1.0, −0.8]−0.06−0.0420.070
은[−1.0, 0.0]−0.90−0.6360.039
평일[0.8, 0.9]1.801.2730.262
오후[0.7, 1.0]1.831.2940.268
9시[0.9, 1.2]2.251.5910.361

출력 = Σ w·v = [0.753, 0.880] (단순 평균 [0.48, 0.46]보다 “시간” 쪽)

의미 2칸 = [내용어(+)·기능어(−), 시간(+)·사물(−)]로 손으로 만든 값이다. W 없이 벡터를 그대로 q·k·v로 쓴 가장 단순한 경우다(Challenge C1과 같은 값).

한 줄(평일)을 칠판에서 끝까지 계산한다: 0.9×0.8 + 1.2×0.9 = 1.80 → ÷1.414 = 1.273 → e1.273 / Σ = 0.262.

발문: “은”의 가중치가 3.9%로 가장 작은 이유는? → 내용어(+)·기능어(−) 칸의 부호가 반대라 내적이 음수다(시간 칸은 0이라 도움이 안 된다).

모든 토큰을 한 번에: 행렬 곱 두 번

Q = X·Wq   K = X·Wk   V = X·Wv          (T×D → T×d)
S = Q·Kᵀ / √d                             (T×T, 행 = 쿼리, 열 = 키)
A = softmax( mask(S) )  ← 행마다          (각 행의 합 = 1)
O = A·V                                   (T×d)
  • Wq·Wk·Wv의 크기는 문장 길이 T와 무관 → 길어져도 파라미터가 늘지 않는다
  • 대신 점수 행렬 S는 T×T → 계산량은 문맥 길이의 제곱

행렬 모양을 칠판에 네모로 그려 “T×d 곱하기 d×T = T×T”를 확인시킨다. 모양 맞추기가 C2에서 가장 많이 막히는 곳이다.

T² 비용은 9주차(메모리 계산기)와 “컨텍스트 창이 왜 유한한가”로 이어진다. 오늘은 한 줄만 언급한다.

데모 · 어텐션 계산기

시연 순서 (결과는 오른쪽 실행 결과 창)

  1. 처음 화면: 앞 토큰 보기 헤드. ④에서 각 쿼리가 바로 앞 토큰에 평균 80%. “9시” → “오후” 78.5%
  2. ① QKᵀ → ② ÷√d → ③ 마스크 → ④ 순서로 눌러 점수가 가중치가 되는 과정을 보인다
  3. ❌ 마스크 끄기 → “실습실”이 마지막 “까지”에 78% (위치가 한 바퀴 돌아 착각). 미래로 간 가중치 평균 20%
  4. 같은 종류 보기 헤드 → “9시”: 평일 22% · 오후 23% · 자기 54%. “까지”는 조사 “은”에 32%
  5. “9시” 칩 → 의미를 [−1.0, 0.0]으로 → “은”과 자기에게 각 48%
  6. 점수 배율 ×2 → 앞 토큰 헤드 평균 최대 가중치 97% (포화 경고)
  7. ❌ d = 64 · 스케일링 끄기 → 평균 최대 가중치 99.8%, 엔트로피 1%. 스케일링만 다시 켜면 71%
  8. 멀티헤드 켜기 → 두 지도가 다르다

인과 마스크: 미래 엿보기 = 반칙

  • 학습: 문장 전체를 한 번에 넣고 모든 위치의 다음 토큰을 동시에 맞힌다
  • 가리지 않으면 “9시” 자리가 바로 뒤 “까지”(= 정답)를 본다
  • 생성할 때는 그 미래가 없다 → 학습과 생성이 어긋난다
S[t][s] = −∞  (s > t)   →   e^−∞ = 0   →   미래 가중치 = 0

검사: 마지막 토큰을 바꿨을 때 앞 5개 출력의 변화 — 마스크 켬 0 · 끔 1.881

숫자는 Challenge C3 정답의 실행 결과다.

발문: “−∞ 대신 −1000을 넣어도 되나?” → 실제로 e−1000은 0으로 계산되므로 동작한다. 단, 행 전체가 −∞이면 max를 빼도 −∞ − (−∞) = NaN이 된다. 인과 마스크는 대각선(자기 자신)을 항상 남기므로 그런 행이 생기지 않는다.

RAG의 문장 임베딩 모델·리랭커는 생성하지 않으므로 마스크 없이 양방향으로 본다. “마스크 끄기 = 항상 틀림”은 아니다.

내적 = d개 항의 합 → 표준편차 ∝ √d · 포화하면 정보도 기울기도 사라진다

무작위 쿼리 500개 × 키 8개, 성분은 표준정규분포(Challenge C4 정답의 실행 결과). 골고루 = 3비트, 원-핫 = 0비트.

포화의 기울기 문제: 소프트맥스 출력 p에 대한 미분은 p(1−p) 꼴이다. p가 0이나 1에 붙으면 0에 가깝다 → 4주차 역전파와 연결.

점수 배율 m = 1/온도. 8주차 디코딩의 온도 손잡이와 같은 수학이라고 예고한다.

위치 정보와 멀티헤드

어텐션은 순서를 모른다

  • 점수 = 내적뿐 → 순서를 섞어도 같은 쌍은 같은 점수
  • 계산기: 임베딩 뒤 2칸 = 위치 [cos 60°t, sin 60°t]
  • “앞 토큰 보기” Wq = 위치를 60° 뒤로 돌리기

멀티헤드

  • Wq·Wk·Wv를 H벌, 각 폭 D/H
  • 결과를 이어 붙여 WO로 섞는다
  • 미니 GPT(7주차): D = 48, H = 4 → 헤드 폭 12

위치를 더하는 표준 방법(학습되는 위치 임베딩)은 6주차 내용이다. 여기서는 “위치가 임베딩에 있어야 앞 토큰 헤드가 가능하다”까지만.

C2의 함정: 마스크 없이 “실습실”은 “까지”를 본다. 위치 원이 6칸마다 한 바퀴 돌아 −1번 위치 = 5번 위치이기 때문이다. 주기가 있는 위치 표현의 한계를 보여 주는 좋은 예다.

실제 모델의 헤드는 학습으로 생긴다. “앞 토큰 보기”처럼 해석되는 헤드가 저절로 생기기도 한다 → 7주차 어텐션 지도.

어텐션 한 층, 코드 15줄

const tokens = ['실습실', '은', '평일', '오후', '9시', '까지'];
const X = [[1.0, -0.8], [-1.0, 0.0], [0.8, 0.9], [0.7, 1.0], [0.9, 1.2], [-0.9, 0.6]];
const Wq = [[2, 0], [0, 2]], Wk = Wq, Wv = [[1, 0], [0, 1]];   // '같은 종류 보기' head
const mm = (A, B) => A.map((r) => B[0].map((_, j) => r.reduce((s, x, p) => s + x * B[p][j], 0)));
const Q = mm(X, Wq), K = mm(X, Wk), V = mm(X, Wv), d = Q[0].length;
const A = Q.map((q, t) => {
  const s = K.map((k, j) => (j > t ? -Infinity : q.reduce((a, x, i) => a + x * k[i], 0) / Math.sqrt(d)));
  const m = Math.max(...s), e = s.map((x) => Math.exp(x - m)), z = e.reduce((a, b) => a + b);
  return e.map((x) => x / z);                                  // causal mask + softmax
});
const O = mm(A, V);                                            // weighted average of values
console.table(Object.fromEntries(A.map((r, t) => [tokens[t], Object.fromEntries(r.map((w, j) => [tokens[j], +w.toFixed(2)]))])));
console.log('9시의 출력:', O[4].map((x) => +x.toFixed(2)));

실행 결과: “9시” 행 = 평일 0.18 · 오후 0.19 · 9시 0.63, “까지” 행 = 은 0.30 · 까지 0.64, 9시의 출력 [0.84, 1.11].

계산기의 같은 헤드는 “9시”에 54%를 주는데 여기는 63%다. 계산기는 Q가 4칸(위치 2칸은 0)이라 √4 = 2로 나누고, 이 코드는 d = 2라 √2로 나누기 때문이다. 같은 점수라도 나누는 값이 작으면 더 뾰족해진다 — √d의 효과를 즉석에서 보여 주는 예로 쓴다.

Math.exp(−Infinity) = 0이라 마스크가 별도 처리 없이 동작한다는 점을 짚는다.

정리

  • 어텐션 출력 = 값의 가중 평균, 가중치 = softmax(q·k / √d) → 내용으로 정한다
  • 인과 마스크: 미래 칸을 −∞로 → 학습과 생성이 일치한다
  • ÷√d: 차원이 커도 소프트맥스가 포화하지 않는다
  • 순서는 위치 정보로, 여러 관점은 멀티헤드로

부록 B · C1 정답

const tokens = ['실습실', '은', '평일', '오후', '9시'];
const E = [[1.0, -0.8], [-1.0, 0.0], [0.8, 0.9], [0.7, 1.0], [0.9, 1.2]];
const d = 2;
const dot = (a, b) => a.reduce((s, x, i) => s + x * b[i], 0);
function softmax(xs) {
  const m = Math.max(...xs);
  const ex = xs.map((x) => Math.exp(x - m));
  const sum = ex.reduce((a, b) => a + b, 0);
  return ex.map((e) => e / sum);
}
const q = E[4];
const scores = E.map((k) => dot(q, k));
const scaled = scores.map((x) => x / Math.sqrt(d));
const weights = softmax(scaled);
console.table(tokens.map((t, i) => ({ key: t, 'q·k': +scores[i].toFixed(3), '÷√d': +scaled[i].toFixed(3), weight: +weights[i].toFixed(3) })));
console.log('가중치 합:', weights.reduce((a, b) => a + b, 0).toFixed(3));
const output = [0, 1].map((j) => weights.reduce((s, w, i) => s + w * E[i][j], 0));
console.log('출력 벡터:', output.map((x) => +x.toFixed(3)));
// Compare: the plain average treats every token the same
const mean = [0, 1].map((j) => E.reduce((s, e) => s + e[j], 0) / E.length);
console.log('단순 평균:', mean.map((x) => +x.toFixed(3)));

실행 결과: q·k = −0.06 / −0.9 / 1.8 / 1.83 / 2.25 · ÷√d = −0.042 / −0.636 / 1.273 / 1.294 / 1.591 · weight = 0.07 / 0.039 / 0.262 / 0.268 / 0.361 · 합 1.000 · 출력 [0.753, 0.88] · 단순 평균 [0.48, 0.46].

자주 틀리는 곳: 소프트맥스에서 max를 빼지 않아도 여기서는 결과가 같다. 하지만 C4에서 d = 256, 스케일링 없이 점수가 수십이 되면 Math.exp가 커져 정밀도가 떨어지고, 수백이면 Infinity/Infinity = NaN이 된다. 처음부터 max 빼기를 습관으로 만든다.

function softmax(xs) {
  const m = Math.max(...xs);
  const ex = xs.map((x) => Math.exp(x - m));
  const sum = ex.reduce((a, b) => a + b, 0);

}

import { Tensor, causalAttention } from '/assets/js/core/tensor.js';
import { mulberry32, gaussian } from '/assets/js/core/rng.js';
const B = 1, T = 5, D = 8, H = 2, hs = D / H;
const rand = mulberry32(5);
const qkv = Array.from({ length: T * 3 * D }, () => gaussian(rand));
const at = (t, col) => qkv[t * 3 * D + col];
function myAttention() {
  const out = new Array(T * D).fill(0);
  const att = Array.from({ length: H }, () => Array.from({ length: T }, () => new Array(T).fill(0)));
  for (let h = 0; h < H; h++) {
    for (let t = 0; t < T; t++) {
      const scores = [];
      for (let s = 0; s <= t; s++) {
        let dot = 0;
        for (let j = 0; j < hs; j++) dot += at(t, h * hs + j) * at(s, D + h * hs + j);
        scores.push(dot / Math.sqrt(hs));
      }
      const m = Math.max(...scores);
      const ex = scores.map((x) => Math.exp(x - m));
      const sum = ex.reduce((a, b) => a + b, 0);
      ex.forEach((e, s) => (att[h][t][s] = e / sum));
      for (let s = 0; s <= t; s++)
        for (let j = 0; j < hs; j++) out[t * D + h * hs + j] += att[h][t][s] * at(s, 2 * D + h * hs + j);
    }
  }
  return { out, att };
}
