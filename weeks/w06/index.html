어텐션에 살을 붙여 GPT를 조립한다

지난주 어텐션은 토큰끼리 정보를 주고받는 장치였다. 그것만으로는 GPT가 되지 않는다. 순서를 모르고, 토큰마다 따로 생각하는 단계가 없고, 여러 층 쌓으면 신호가 사라지거나 터진다. 이번 주는 위치 임베딩, 피드포워드, 잔차 연결, 층 정규화를 붙여 7주차에 학습시킬 미니 GPT를 부품 하나하나까지 조립하고, 텐서 모양과 파라미터 수를 직접 따라간다.

1학습 목표

이번 주가 끝나면
  • 미니 GPT의 순전파를 따라가며 각 지점의 텐서 모양([B, T, D], [B, H, T, T], [B, T, V])을 적을 수 있다.
  • 어텐션에 위치 정보가 필요한 이유(순서를 섞어도 결과가 같다)와 잔차 연결·층 정규화가 하는 일을 설명할 수 있다.
  • 설정값(V, T, L, D)으로 파라미터 수를 세고(블록 하나 ≈ 12·D²), core/gpt.js의 paramCount로 검증할 수 있다.

2왜 필요한가

5주차 어텐션 계산기로 돌아가 보자. 어텐션은 질의(Q)와 키(K)의 내적으로 가중치를 정하고, 값(V)을 그 가중치로 섞었다. 이것 하나만 가지고 언어 모델을 만들면 세 가지가 곧바로 막힌다.

  1. 순서를 모른다. 가중합은 “무엇이 있었나”만 보고 “어디에 있었나”는 보지 않는다. “5-3=”과 “3-5=”를 넣으면 마지막 토큰 “=”이 받는 결과가 완전히 같다. 답은 2와 −2로 다른데 모델에게는 같은 입력이다.
  2. 섞기만 하고 생각하지 않는다. 어텐션의 출력은 값 벡터들의 가중 평균이다. 모은 정보를 토큰마다 비선형으로 가공하는 단계가 따로 있어야 한다.
  3. 깊이 쌓을 수 없다. 층을 수십 개 쌓으면 신호가 층마다 조금씩 줄거나 늘어, 결국 0으로 사라지거나 수만 배로 터진다. 역전파 기울기도 마찬가지다.
트랜스포머 블록 = 교환 + 생각 + 배관

어텐션(토큰끼리 정보 교환)과 피드포워드(토큰마다 따로 생각)를 번갈아 두고, 층 정규화와 잔차 연결이라는 “배관”으로 깊이 쌓아도 신호가 흐르게 한다. 맨 앞에서는 위치 임베딩으로 순서를 알려 준다. GPT는 이 블록을 L번 쌓은 것이 전부다.

3개념

전체 구조: 임베딩 → 블록 × L → 헤드

GPT-2와 우리 미니 GPT(core/gpt.js)의 구조는 같다. 크기만 다르다. 각 층 앞에 층 정규화가 있고, 각 층의 출력은 입력에 더해진다. 이렇게 입력을 그대로 더해 주는 연결을 잔차 연결(residual connection)이라 한다.

텐서 모양 따라가기

순전파를 이해하는 가장 빠른 방법은 각 지점을 지나는 텐서의 모양을 적어 보는 것이다. 7주차에 학습할 미니 GPT(V = 495, T = 48, L = 2, H = 4, D = 48)로 배치 B = 1인 경우를 적으면 다음과 같다. 헤드 하나의 크기는 hs = D / H = 12다.

지점모양미니 GPT (B = 1)하는 일
입력 토큰 id[B, T][1, 48]글자 번호 48개
임베딩 합[B, T, D][1, 48, 48]토큰마다 48차원 벡터

두 가지를 눈여겨본다. 첫째, 블록을 지나도 모양은 [B, T, D] 그대로다. 그래서 블록을 몇 개든 쌓을 수 있다. 둘째, 어텐션 점수만 T가 두 번 들어간다. 문맥 길이를 2배로 늘리면 다른 텐서는 2배, 어텐션 점수는 4배가 된다. core/gpt.js는 계산을 단순하게 하려고 [B, T, D]를 [B·T, D]로 펼쳐 저장한다. 로짓의 shape가 [48, 495]로 찍히는 이유다.

위치 임베딩: 어텐션은 순서를 모른다

마지막 토큰의 어텐션 출력은 Σs softmax(q · ks) vs, 즉 앞 토큰들에 대한 합이다. 합은 더하는 순서와 상관없다. 토큰 벡터가 “어떤 글자인가”만 담고 있으면 앞 토큰들을 어떻게 섞어도 가중치는 토큰을 따라다니고 결과는 똑같다. 수학에서는 이 성질을 순열 불변(permutation invariance)이라 한다.

해결은 간단하다. 토큰 임베딩에 위치 임베딩(position embedding)을 더해 “몇 번째 토큰인지” 알려 준다. 그러면 같은 글자라도 자리마다 벡터가 달라진다.

x[t] = wte[토큰 id] + wpe[t]        // t = 0, 1, …, T−1
  • 학습형(GPT-2, 우리 미니 GPT): 위치마다 D차원 벡터 한 줄씩, T × D 표를 두고 학습으로 채운다. 표에 없는 위치(T 이상)는 쓸 수 없다. 미니 GPT가 48글자까지만 보는 이유다.
  • 사인파(원조 트랜스포머, 2017): 학습 없이 여러 주기의 sin · cos 값을 쓴다. 실습의 히트맵에서 무늬를 본다.
  • 요즘 LLM은 대부분 RoPE를 쓴다. 벡터에 더하지 않고 Q와 K를 위치만큼 회전시켜, 점수 q · k에 “두 토큰이 얼마나 떨어져 있나”가 들어가게 한다.

한 가지 단서가 있다. 인과 마스크를 쓰는 층을 여러 개 쌓으면 “내 앞에 토큰이 몇 개 있나”가 간접적으로 새어 들어가, 위치 임베딩이 없어도 순서가 조금은 드러난다(C5에서 확인한다). 하지만 약하고 간접적이라 GPT는 위치 정보를 명시적으로 넣는다.

잔차 연결: 입력을 그대로 더한다

블록 안의 두 층은 x를 바꾸지 않고 변화량만 더한다.

x = x + 어텐션(층정규화(x))
x = x + 피드포워드(층정규화(x))

이렇게 하면 어떤 층이 쓸모없는 값을 내도 원래 x는 그대로 남는다. 역전파에서도 x + f(x)의 미분은 1 + f′(x)라서, 기울기가 “1” 경로를 타고 맨 아래 층까지 줄지 않고 내려간다. 64차원 벡터를 무작위 선형 층 48개에 통과시켜 보면 차이가 뚜렷하다(C3).

설정 (층 48개)|x| 입력 → 48층입력 쪽 기울기 크기
잔차 없음 · 층이 신호를 0.8배7.81 → 0.0000634 (소실)0.0000135
잔차 없음 · 층이 신호를 1.2배7.81 → 18,000 (폭발)3,830
잔차 있음 · 더하는 양 0.1배7.81 → 10.21.33

잔차가 있어도 더하는 양이 크면 다시 폭발한다. 그래서 GPT-2(와 core/gpt.js)는 잔차에 더해지는 투영 층을 처음에 1/√(2L)배 작게 초기화한다.

층 정규화: 토큰마다 평균 0, 분산 1

층 정규화(layer normalization)는 토큰 하나의 D차원 벡터를 평균 0, 분산 1로 맞춘 뒤, 학습하는 γ(배율)와 β(이동)를 곱하고 더한다.

y = γ · (x − 평균) / √(분산 + ε) + β        // 벡터 [2, 4, 4, 4, 5, 5, 7, 9] → [−1.5, −0.5, −0.5, −0.5, 0, 0, 1, 2]

잔차 흐름은 층을 지날수록 값의 크기가 제각각 커진다. 각 층 입구에서 정규화하면 어텐션과 피드포워드는 늘 비슷한 크기의 입력을 받는다. 입력을 100배 하고 1000을 더해도 결과가 같다(C2). GPT-2처럼 층 앞에 두는 방식을 pre-norm이라 하고, 마지막 블록 뒤에도 한 번 더 둔다(최종 층 정규화).

피드포워드: 토큰마다 따로 생각한다

피드포워드(feed-forward) 층은 벡터 차원을 네 배로 늘렸다가 다시 줄이는 두 개의 선형 층과 그 사이의 활성화 함수(GELU)다. 어텐션이 토큰끼리 정보를 모았다면, 피드포워드는 모은 정보를 토큰마다 독립적으로 가공한다. 같은 가중치를 T개 위치에 똑같이 적용한다. 블록 파라미터의 2/3가 여기에 있다.

🤖

머신러닝 기초와 연결 — 피드포워드는 머신러닝 기초의 “신경망” 단원에서 만든 은닉층 하나짜리 다층 퍼셉트론(MLP) 그대로다. 선형 → 활성화 → 선형. 다른 점은 ReLU 대신 부드러운 GELU를 쓰고, 문장의 모든 토큰에 같은 MLP를 적용한다는 것뿐이다.

블록 하나는 행렬 D×3D, D×D, D×4D, 4D×D로 12·D²개가 거의 전부다. 헤드 수 H는 파라미터 수에 들어가지 않는다. 헤드는 qkv 행렬을 나눠 쓰는 방식일 뿐이다. 미니 GPT는 D가 작아서 임베딩과 헤드(V·D에 비례)가 전체의 47%를 차지한다. GPT-2 small(V 50,257 · T 1,024 · L 12 · D 768)은 같은 공식에 출력 헤드를 wte와 공유(헤드 편향 없음)해서 정확히 124,439,808개다. 우리 구조처럼 헤드를 따로 두면 163,087,441개가 된다.

① 트랜스포머 해부도

설정을 바꾸면 블록 그림의 화살표마다 텐서 모양이 바뀌고, 오른쪽 실행 결과 창(휴대폰에서는 위젯 아래)에 파라미터 표와 메모리 어림이 나온다. 처음 화면은 7주차에 학습할 미니 GPT다.

관찰 질문

  1. 미니 GPT에서 총 파라미터와 “임베딩 + 헤드 비중”을 적는다. 블록 하나의 수가 12·D² = 27,648과 얼마나 가까운가?
  2. H를 1 → 4 → 12로 바꾼다. 어느 화살표의 모양이 바뀌고, 파라미터 수는 어떻게 되는가? H = 5로 두면 무슨 일이 생기는가?
  3. T를 48 → 96 → 1,024로 늘린다. 파라미터는 얼마나 늘고, “어텐션 점수 L·H·T²” 메모리는 얼마나 느는가? 둘의 증가 속도를 비교한다.
  4. “GPT-2 small”을 누르고 124,439,808을 확인한다. 공유 체크를 끄면 몇 개가 되는가? fp16으로 저장하면 몇 MB인가?
  5. “큰 어휘 + 작은 모델”을 누른다. 블록이 전체의 몇 %인가? 이 모델에 파라미터를 더 준다면 V·D와 L·D² 중 어디를 키우겠는가?

② 위치 정보가 없으면

문장의 마지막 글자는 그대로 두고 앞 글자들을 뒤집거나 섞어, 층 정규화 + 어텐션 한 층에 넣는다. 위치 정보가 없을 때와 있을 때 마지막 토큰의 출력이 얼마나 다른지 비교한다.

관찰 질문

  1. 처음 화면 “5-3=” vs “3-5=”에서 위치 정보가 없을 때 |Δ|는 얼마인가? 0이 아니라 아주 작은 수가 나오는 이유는 무엇인가? (힌트: 부동소수점 덧셈의 순서)
  2. 가중치 표에서 “5”가 받은 가중치를 원래 순서와 섞은 순서로 비교한다. 위치 정보가 있을 때는 어떻게 되는가?
  3. 🔀를 여러 번 누르고, 문장도 바꿔 본다. 위치 정보 없는 쪽의 |Δ|가 커지는 경우가 있는가?
  4. 위치 정보를 “사인파”로 바꾼다. 학습형과 비교해 |Δ|는 어떤가? 둘 다 순서를 구별하게 해 주는가?
  5. 사인파 히트맵에서 왼쪽 열과 오른쪽 열의 무늬를 비교한다. 위치 0과 1의 행은 비슷한가, 위치 0과 40의 행은 어떤가?

C1. 텐서 모양 장부★

설정과 B, T를 받아 순전파의 각 지점에서 텐서 모양과 원소 수를 표로 돌려주는 traceShapes를 완성한다. B = 4, T = 48로 출력하고, core/gpt.js가 돌려준 로짓 모양 [192, 495]가 표의 어느 줄을 펼친 것인지 확인한다. 기대 결과: 어텐션 점수 [4, 4, 48, 48], T를 2배로 하면 어텐션 점수는 4배, qkv는 2배.

import { createModel, forward } from '/assets/js/core/gpt.js';

  const add = (stage, shape) => rows.push({ stage, shape: `[${shape.join(', ')}]`, count: shape.reduce((a, b) => a * b, 1) });
  add('입력 토큰 id', [B, T]);

C3. 잔차 연결 실험★★★

64차원 벡터를 무작위 선형 층 48개에 통과시킨다. 잔차가 없으면 x = W·x, 있으면 x = x + W·x다. 층마다 벡터 크기 |x|, 마지막 층과 입력의 방향 유사도 cos, 그리고 역전파로 입력까지 내려온 기울기 크기를 비교한다. 기대 결과는 개념 절의 표와 같다.

import { mulberry32, gaussian } from '/assets/js/core/rng.js';
const D = 64, DEPTH = 48;
const norm = (v) => Math.sqrt(v.reduce((s, x) => s + x * x, 0));
const cos = (a, b) => a.reduce((s, x, i) => s + x * b[i], 0) / (norm(a) * norm(b));
const matVec = (W, v) => W.map((row) => row.reduce((s, w, j) => s + w * v[j], 0)); // W · v
const matTVec = (W, g) => W[0].map((_, j) => W.reduce((s, row, i) => s + row[j] * g[i], 0)); // Wᵀ · g

/** DEPTH개의 무작위 층 W (D×D). 원소는 평균 0, 표준편차 gain/√D. */
function makeLayers(gain, seed = 1) {
  const rand = mulberry32(seed);
  return Array.from({ length: DEPTH }, () => Array.from({ length: D }, () => Array.from({ length: D }, () => (gaussian(rand) * gain) / Math.sqrt(D))));
}

function run(gain, residual) {
  const layers = makeLayers(gain);
  const r = mulberry32(99);
  const x0 = Array.from({ length: D }, () => gaussian(r));
  let x = x0;
  const norms = [norm(x)];
  for (const W of layers) {
    const f = matVec(W, x);
    // TODO: residual이면 x = x + f, 아니면 x = f
    norms.push(norm(x));
  }
  // 역전파: 맨 위에서 크기 1인 기울기 g를 아래로 보낸다
  let g = Array.from({ length: D }, () => 1 / Math.sqrt(D));
  for (let l = DEPTH - 1; l >= 0; l--) {
    const back = matTVec(layers[l], g);
    // TODO: residual이면 g = g + back (x + f의 미분은 I + W), 아니면 g = back
  }
  return { norms, cosIn: cos(x, x0), grad: norm(g) };
}

const rows = [];
for (const [gain, residual] of [[0.8, false], [1.0, false], [1.2, false], [0.1, true], [0.5, true]]) {
  const res = run(gain, residual);
  rows.push({
    설정: `${residual ? '잔차 있음' : '잔차 없음'} · gain ${gain}`,
    '|x| 0층': +res.norms[0].toFixed(2),
    '|x| 12층': +res.norms[12].toPrecision(3),
    '|x| 48층': +res.norms[DEPTH].toPrecision(3),
    'cos(x48, x0)': +res.cosIn.toFixed(3),
    '입력 기울기 |g|': +res.grad.toPrecision(3),
  });
}

6정리 & 다음 주 예고

  • GPT = 토큰 임베딩 + 위치 임베딩 → [층 정규화 → 인과 어텐션 → 잔차 더하기 → 층 정규화 → 피드포워드 → 잔차 더하기] × L → 최종 층 정규화 → 출력 헤드.
  • 블록을 지나도 모양은 [B, T, D]로 같다. 어텐션 점수만 [B, H, T, T]라서 문맥 길이의 제곱으로 커진다.
  • 어텐션은 합이라서 순서를 모른다. 위치 임베딩(학습형 wpe, 사인파, RoPE)으로 순서를 넣는다.
  • 잔차 연결은 신호와 기울기의 고속도로, 층 정규화는 각 층 입구의 크기 조절기, 피드포워드는 토큰별 MLP다.
  • 블록 하나 ≈ 12·D². 작은 모델은 임베딩과 헤드(V·D)가 큰 비중을 차지한다. 미니 GPT는 106,959개, GPT-2 small은 124,439,808개다.
