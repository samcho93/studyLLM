수업 전 필수: ① 모델 표는 2026-09-24에 공식 문서로 확인한 값이다. 수업일이 한 달 이상 지났다면 GPT · Claude · Gemini 모델 페이지를 한 번 열어 이름이 바뀌었는지 본다(바뀌었다면 그 자체가 “빠르게 바뀐다”의 예시). ② 교탁 PC에 Ollama를 설치하고 ollama pull qwen3.5:0.8b를 미리 받아 두면 “실행 5가지” 슬라이드에서 터미널 시연이 가능하다(선택). ③ 브라우저 실행 버튼은 16주차와 같은 SmolLM2-135M(137MB) 캐시를 쓴다.

오늘 할 수 있게 되는 것

  1. 대표 LLM을 공개 여부 · 컨텍스트 · 입력 · 라이선스 · 한국어로 비교한다
  2. sLLM이 쓸 만해진 이유를 설명하고 파라미터 × 비트 ÷ 8로 메모리를 잰다
  3. 오픈소스 ≠ 오픈 웨이트를 구분해 모델을 고르고 다섯 가지 방법으로 실행한다

과정의 마지막 주다. 7주차(직접 학습) → 11주차(API) → 16주차(브라우저 로컬)에 이어 “실무에서 모델을 고르고 붙이는 법”으로 마무리한다는 틀을 먼저 준다. 모델 이름은 외울 대상이 아니라는 점을 처음부터 강조한다.

상담 기록 요약 도우미, 어떤 모델?

  • “허깅페이스에 있으니 오픈소스다”
  • “컨텍스트 1M이니 긴 문서에 쓰면 된다”
  • “4B니까 4GB면 된다”

셋 다 틀릴 수 있다

발문: 학생 상담 기록 요약 → 11주차 API는 데이터가 밖으로, 16주차 135M은 한국어 불가. “그럼 무엇?”을 묻고 세 가지 믿음에 손을 들게 한다. 각각 라이선스(EXAONE NC), 크기(1M 컨텍스트 모델은 수백 B이거나 API 전용), 비트 수 · KV 캐시로 오늘 반박한다.

“오픈소스”는 OSI 승인 라이선스를 가리키는 말이다. 가중치만 공개하고 사용 조건을 맞춤 약관으로 걸면 “오픈 웨이트”가 정확한 말이다. models.json 기준 오픈 웨이트 42개 중 14개가 OSI 라이선스가 아니다(C3 정답).

출처는 모두 models.json의 source 칸(공식 모델 페이지)이다. 파라미터 수는 API 모델이 공개하지 않으므로 비교할 수 없다 → 비교표 탐색기 산점도에서 “비공개” 띠로 따로 모인다.

강조할 흐름: ① 컨텍스트 1M이 흔해졌다 ② 큰 회사도 오픈 웨이트를 함께 낸다 ③ 국내 기업도 API와 오픈 모델을 병행한다. 가격은 수시로 바뀌어 싣지 않았다고 말한다. Muse Spark는 2026-04 보도 기준 비공개 · 제한 미리보기이며 공개 사양이 없다.

sLLM: 대략 0.5B~15B

왜대가
비용 · 토큰 요금 없음지식이 적다 → 환각
개인정보가 밖으로 안 나감여러 단계 추론에 약하다
지연 · 오프라인한국어 데이터가 적으면 품질 · 토큰 손해
LoRA 미세조정 가능 (10주차)긴 창 ≠ 긴 문맥을 잘 씀

“sLLM”은 국내 업계에서 많이 쓰는 말이고 영어권은 SLM(small language model)을 더 쓴다. 정해진 경계는 없다고 분명히 한다. 16주차 135M은 “초소형”으로 부른다.

작은데 쓸 만해진 이유

  • 증류: R1 → R1-Distill-Qwen 1.5B · 7B · Kanana-2 1.3B(가지치기 + 증류)
  • 데이터 품질: Phi(합성 데이터) · SmolLM2-1.7B(FineWeb-Edu 등 11조 토큰)
  • 양자화: 16주차 · 4비트 = 16비트의 1/4
  • 어텐션 절약: GQA(6주차) · 슬라이딩 윈도 (Kanana-2: KV 캐시 최대 약 72.7%↓)
  • 다 쓰지 않기: MoE (gpt-oss-20b 활성 3.6B) · Gemma 4 E2B(유효 2.3B / 전체 5.1B)

숫자는 모두 모델 카드의 자체 설명이다(벤치마크 아님). 9주차 스케일링 법칙의 세 축(파라미터 · 데이터 · 계산)을 떠올리게 하고, “파라미터를 줄이는 대신 데이터와 교사 모델로 메운다”로 요약한다.

C2 정답 실행 결과다(파일 크기는 허깅페이스 저장소의 실제 바이트). 1.0에서 벗어나는 두 경우를 설명한다. 0.91: 멀티모달 모델은 비전 · 음성 인코더가 별도 mmproj 파일로 빠져 본 파일에 없다(Ministral 3 3B도 0.89). 1.29: 작은 모델일수록 어휘 표의 비중이 커서, 임베딩 · 출력층을 어떻게 저장하느냐가 크기를 흔든다(16주차 “q4가 int8보다 큰” 사례와 같은 이유).

Q4_K_M은 텐서마다 비트를 섞는 형식이라 순수 4비트 계산보다 1.1~1.3배(작은 모델은 최대 약 2배) 크다.

각 저장소 LICENSE 원문을 요약한 것이며 법률 자문이 아니라고 말한다. 핵심 메시지: “회사 이름이 아니라 저장소마다 LICENSE를 연다.” Kanana 1.5는 Apache-2.0, Kanana-2는 Kanana Open License라는 점도 같은 예다. Gemma 3(맞춤 약관) → Gemma 4(Apache-2.0)로 바뀐 것도 짚는다.

데모 · LLM 비교표 탐색기

시연 순서

  1. 초기 상태(외부 전송 불가 + GPU 없음 + 한국어 + 상업) → 후보 8개. “아깝게 탈락” 첫 줄이 EXAONE 4.0 1.2B(비상업)
  2. “상업 서비스” 체크 해제 → EXAONE이 들어와 9개. 수업 과제와 창업의 차이
  3. “긴 문서(≥128K)” 체크 → 노트북 · 한국어 조건과 함께면 Phi-4-mini · Ministral 3 3B만 남는다
  4. 산점도: 1M 점들은 모두 비공개 띠이거나 100B 이상. 초록 노트북 영역 안에 1M 점은 없다
  5. 라이선스 필터 “OSI 오픈소스만” → 결과 창 “오픈 웨이트 42 · 그중 OSI 28”

코드로 보면: 두 API 형식

const messages = [{ role: 'user', content: '실습실은 몇 시까지 여나? JSON으로.' }];
const ollama = { model: 'qwen3.5:0.8b', messages, stream: false, format: 'json', options: { temperature: 0 } };
const openai = { model: 'qwen3.5:0.8b', messages, stream: false, temperature: 0, response_format: { type: 'json_object' } };
const only = (a, b) => Object.keys(a).filter((k) => !(k in b));
console.log('POST /api/chat →', JSON.stringify(ollama));
console.log('POST /v1/chat/completions →', JSON.stringify(openai));
console.log('Ollama에만:', only(ollama, openai), '· OpenAI에만:', only(openai, ollama));

실행 결과: Ollama에만 format · options, OpenAI에만 temperature · response_format. messages는 같다 → 10주차 채팅 형식이 공통어. 기본 스트리밍 여부도 다르다(Ollama /api/chat은 스트리밍이 기본). C4로 이어진다.

데모 · sLLM 사용법 스니펫

시연 순서

  1. 초기: Ollama × Qwen3.5-0.8B × JSON 추출 × 4비트 → format: "json" 확인
  2. 모델을 Kanana 1.5 2.1B로 → Ollama · llama.cpp · 브라우저에서 ✗ (확인된 GGUF · ONNX 없음). transformers · vLLM은 ✓
  3. EXAONE 4.0 1.2B → 모든 방식에 ⛔ 비상업 경고, Ollama는 hf.co/… GGUF 경로로 대체
  4. Gemma 4 E2B × 16/8/4비트 → 계산값과 실제 GGUF 비교 (유효 2.3B · 전체 5.1B)
  5. ▶ 브라우저 실행 (JSON 추출) → SmolLM2-135M은 JSON.parse 실패. 형식 강제와 한국어 모델이 왜 필요한지로 마무리

  2. 미니 GPT 학습 · 디코딩 · 평가 · 스케일링 · 채팅 템플릿 · LoRA
  3. API · 한계와 RAG · 텍스트 처리 · 챗봇 · 에이전트 · 로컬 LLM
  4. 모델 고르기: 조건으로 거르고 → 우리 데이터로 평가

const data = await (await fetch('/assets/data/w17/models.json')).json();
const { models, licenses } = data;
console.log('모델 수:', models.length, '· 기준일', data.asOf);
const small = models.filter((m) => licenses[m.license].weights && m.paramsB !== null && m.paramsB <= 4);
const korean = small.filter((m) => m.korean === '특화' || m.korean === '명시');
const sorted = [...korean].sort((a, b) => a.paramsB - b.paramsB);
console.table(sorted.map((m) => ({ name: m.name, paramsB: m.paramsB, ctx: m.ctx, license: licenses[m.license].label, korean: m.korean })));
console.log('상업 이용 불가:', sorted.filter((m) => licenses[m.license].commercial === 'no').map((m) => m.name));

const { models } = await (await fetch('/assets/data/w17/models.json')).json();
const withGguf = models.filter((m) => m.runtimes?.gguf);
console.log('GGUF 파일 크기를 아는 모델:', withGguf.length);
const BITS = { F16: 16, BF16: 16, Q8_0: 8 + 16 / 32, Q4_0: 4 + 16 / 32 };
const weightGB = (paramsB, bits) => (paramsB * bits) / 8;
const r2 = (x) => Math.round(x * 100) / 100;
const rows = [];
for (const m of withGguf) {
  const g = m.runtimes.gguf;
  const params = g.lmParamsB ?? m.paramsB;
  const row = { name: m.name, paramsB: params, fp16: r2(weightGB(params, 16)), int8: r2(weightGB(params, 8)), int4: r2(weightGB(params, 4)) };
  if (g.files.Q8_0) {
    row.q8Real = r2(g.files.Q8_0 / 1e9);
    row.q8Ratio = r2(g.files.Q8_0 / 1e9 / weightGB(params, BITS.Q8_0));
  }
  const q4 = g.files.Q4_K_M ? 'Q4_K_M' : g.files.Q4_0 ? 'Q4_0' : null;
  if (q4) {
    row.q4File = q4;
    row.q4Real = r2(g.files[q4] / 1e9);
    row.q4VsInt4 = r2(g.files[q4] / 1e9 / weightGB(params, 4));
  }
  rows.push(row);
}
console.table(rows);
const maxB = (8 * 8) / 4;
